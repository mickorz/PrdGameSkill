# Game PRD Check Skill

读取 `input/` 下的原始 PRD 需求文档，对照 `references/rules/` 下的检查规范（规则基准，视为正确答案），逐项检查并生成问题报告到 `examples/game-prd-check/report.md`。

## 执行流程（四步）

1. **读取 input**：读取 `input/` 下的需求文档（全文，必要时分段读取）。
2. **读取 rules**：读取 `references/rules/` 下对应的检查规范。规则较多时按目录分组加载，确保每份规范都被对照过。
3. **AI 检查**：以 rules 为基准逐项检查需求文档，发现五类问题（见下）。
4. **输出 report.md**：按 `references/templates/report.template.md` 的四段结构生成报告，写入 `examples/game-prd-check/report.md`。

## 问题类型（五种，只允许这五种）

| 类型 | 含义 | 判定标准 |
|---|---|---|
| MISSING | 内容缺失 | rules 中定义了、但需求文档缺失或未描述 |
| CONFLICT | 内容冲突 | 需求文档内部两处描述互相矛盾 |
| LOGIC | 规则逻辑问题 | 与 rules 基准冲突或自身逻辑错误 |
| AMBIGUOUS | 描述模糊 | 可多种理解，无法确定实现方式 |
| INCOMPLETE | 描述不完整 | 无法实现或无法验收 |

## 优先级定义

| 优先级 | 判定标准 |
|---|---|
| P0 | 关键流程/规则缺失或矛盾，直接阻塞开发或验收 |
| P1 | 明确的冲突、逻辑错误，不解决会导致实现错误 |
| P2 | 模糊、不完整，需要澄清后才能实现 |
| P3 | 优化建议，不影响正确性，但补充后文档质量更高 |

## 硬性要求

1. **证据先行**：每个问题必须给出需求文档的原文位置（章节/小节标题）和原文引文，不允许无依据推测。
2. **以 rules 为准**：需求文档与 rules 冲突时，记问题的是需求文档，不是 rules。
3. **不臆造**：需求文档确实没写才算 MISSING；写了但含糊才是 AMBIGUOUS/INCOMPLETE。
4. **不重复**：同一问题只记一条，多处证据合并到同一条的原文位置里。

## 报告结构

四部分，详见 `references/templates/report.template.md`：

1. 检查概览（统计表）
2. 问题清单（核心表格：ID | 类型 | 优先级 | 问题 | 原文位置 | 建议）
3. 重点问题详情（逐条展开：原文、问题、影响、建议、处理状态）
4. 总体建议（问题最多的模块、影响开发的问题、是否建议进入下一阶段）

问题 ID 格式：`PRD-001` 起连续编号。处理状态默认"待确认"。

## 输出位置

`examples/game-prd-check/report.md`（唯一交付物）。
