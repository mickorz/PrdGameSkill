# 等待结束

**什么时候出现**：服务端在某个动画/流程后要求客户端确认（客户端播完动画后回应）。

## 一、数据上记录了什么

- 记录本次确认所需的询问编号。
- 如果当前处于“非第一局的发牌阶段”，会自动回应一次服务端，然后结束。

## 二、界面变化

- 本消息**自身不改变任何界面元素**。
- 唯一的可见影响来自它推动流程：回应服务端后，服务端会继续下发后续消息（例如开始发牌、摸牌），从而产生对应表现。

## 三、连带影响

- 回放模式下不会真的回应服务端，因此回放不会推动真实对局。
- 开局动画、翻财神、跟庄、洗牌、摊牌等多处动画结束时都会回应一次服务端，询问编号由本消息维护。编号丢失会导致界面“卡在等待”。

## 四、重连 / 回放

只补数据时不回应、不改界面。
