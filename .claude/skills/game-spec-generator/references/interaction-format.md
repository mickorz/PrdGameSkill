# Interaction 格式规范


## 职责

回答「玩家如何操作」。承载页面、控件、交互、反馈、状态。

## 必须覆盖的章节

1. 文档状态
2. 事实溯源汇总 + 复用原始 UI 需求清单（不重复发明已有交互）
3. 全局交互原则
4. 全局导航表（入口/目标页/高亮/红点）
5. 全局状态表（loading/offline 等）
6. 分页面交互：目的、进入来源、离开去向、主流程、控件与行为表、状态机表、弹窗/二次确认
7. 跨页链路
8. 验收清单（每个主操作能映射到 Contract 条目）

## 硬性规则

- 充分复用原始 UI 需求文档（如 08-UI交互.md）的内容；继承项要列明，差异项要标记
- 每个控件行为含：操作、前置条件、成功结果、失败/空态
- 每个页面至少一个状态机与一种失败/空态
- 每个主操作必须能被 Interaction-Contract.yaml 引用（通过 INT-xxx ID）
- 交互细节原文未定义的标「待确认」，不得按常见竞品惯例补全
