## 检查口径

1. 每条规则按"UI 事实"陈述（界面区域、变化、条件）；检查需求文档时问三个问题：需求是否定义了这个交互？定义与基准是否一致？需求是否遗漏了基准中存在的边界（失败/超时/重连）表现？
2. 需求文档写明"本期不做/按无托管处理"的项不报缺失（如杭麻需求文档明示头像不显示托管图标）。
3. 交互限制四类（前置守卫/互斥/超时/失败与恢复）是重点检查维度：基准中每条都有明确实现，需求文档缺失即报 INCOMPLETE。
4. 基准中标注"死代码/无消费方"的项（如 CMD_JOKER 无处理类、报听已移除）不作为要求需求文档覆盖的依据，但需求文档若描述了这些行为，与实现不符时记 CONFLICT。
