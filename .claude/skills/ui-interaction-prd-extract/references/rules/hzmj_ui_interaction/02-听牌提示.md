# 听牌提示（客户端 UI 交互基准）

> 来源：42319 代码逆向。检查需求文档对听牌提示体系（查听/打听/箭头/弹窗/按钮）的描述完整性。

## 一、数据与分类

1. 听牌信息可能分多条下发（START/END/ALL 标记），客户端合并计算。锚点：controller/cmd/gameCmd/GameWaitInfoCmd.ts → execute
2. 两类听牌数据：查听（已听牌态，play_mah==0）与打听（打哪张听什么，play_mah!=0）；同包混合时先写查听再刷打听箭头。锚点：GameWaitInfoCmd.ts → _modifyTingInfo
3. 听型分类：大听（存在显著更大倍数的听牌）、多听（张数比最少多 2 张以上）、优听（四张全在手）；箭头样式按听型区分。锚点：data/GameData.ts → calcCanTingInfo；BoxMahDefine.ts → TingType
4. 听牌剩余数按记牌数据实时计算（每张听牌剩余张数、总张数、总收益、最大倍数，受封顶截断，0 倍按 1 倍兜底）。锚点：GameData.ts → calcTingInfo
5. 自己胡后听牌数据强制清空、胡牌确认时清箭头并关听牌弹窗。锚点：GameData.ts → setCanTingVaule；GameHuExCmd → _dispatchSetHu

## 二、听牌箭头（手牌标记）

6. 打听箭头显示在手牌上（同牌值只标第一张），带听型样式（普通/大/多/优）；出牌后仍保留有效箭头。锚点：layer/BoxHzmjPlayerHandCards.ts → showTingArrow；Mah2DBase → setCardTing
7. 杭麻需求文档中的"听牌标签优先级：优>大>多>箭头"对应此听型分类体系，需求数值规则（张数/倍数阈值）归玩法规则，本基准只管 UI 表现。

## 三、查听按钮与听牌弹窗

8. 常驻听牌组件含查听按钮 + 自动胡按钮；查听按钮显示条件：有已听牌数据且自己未胡；显示/隐藏时机（出牌后显、摸牌后隐、有出牌权限隐、自己胡/局终隐、点击桌面隐）。锚点：layer/BoxHzmjMainView.ts → showTingPaiBtn / checkShowTingBtnOnPlay 等
9. 听牌列表弹窗排序：番数降序 + 牌值升序；每项 = 牌面 + 倍数 + 剩余张数；剩余 0 张牌面置灰；总张数 + 封顶文案（"无封顶"或"封顶N倍"）。锚点：layer/BoxHzmjTingPaiView.ts → initUI / itemRender
10. 弹窗打开两个入口：点查听按钮（重复点击切换关闭）、提牌时该牌可听则自动弹（只显示打这张牌后的听型）。锚点：BoxHzmjMainView.ts → onBtnTing / onUpDownMah
11. 弹窗关闭时机：出牌后、摸牌时、自己可胡时、自己胡时、流局摊牌、点桌面空白、重置。锚点：BoxHzmjMainView.ts 各 checkShowTingBtnOn*；GameDrawnCmd
12. 长按桌面 0.3 秒且持有记牌器道具时弹出记牌器，松手关闭；点击牌数区域也可打开。锚点：BoxHzmjMainView.ts → touchTick / onClickCardCount
