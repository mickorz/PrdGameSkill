# ui-interaction-prd-extract 输出结构与规范

## 输出目录结构

```
examples/ui-interaction-prd-extract/
  模块分析.md                  # 总入口：模块概述 + 流程 loop 概览 + 全部索引
  界面分析.md                  # 界面总表：分层关系、打开方式、界面关系图
  流程分析.md                  # 按游戏流程串联：阶段 → 界面 → 事件时序
  界面/                        # 每个界面一个文档（代码 layer/ 下的 XxxView/XxxLayer）
    BoxKaWuXingMahMainView.md
    ...
  组件/                        # 仅【有交互逻辑/状态/事件】的组件单独成文
    BoxKaWuXingPlayerHandCards.md
    ...
```

## 划分标准

### 界面（界面/ 目录）

以代码 `layer/` 目录下的每个 `XxxView` / `XxxLayer` 为准，一一对应 FGUI 包里的 component（通过代码 `@FguiView({ fguiObject: "Xxx" })` 确认映射）。全屏界面、弹窗、提示层都是界面。

### 组件（组件/ 目录）

**仅交互组件单独成文**，满足任一条件即"交互组件"：

1. 有用户输入交互（点击、拖动、长按等）
2. 有独立的内部状态需要维护（如手牌的举起/放下/置灰）
3. 会触发或监听事件（网络事件或内部事件）

纯静态展示组件（装饰图、图片组合、纯文本）不单独成文，在所属界面文档的"组件清单"表格中列一行说明即可。

### 事件

- **网络事件**：`protocol/gameCmd/`（收）+ Controller 的 send 方法（发）。文档中只写 **Cmd 名 + 方向（收/发）+ 触发时机**，协议字段明细统一汇总在 `模块分析.md` 的附录协议索引中。
- **内部事件**：`@gf.listen(...)` 监听的 GameEvent / ViewEvent、`dispatch(...)` 派发的事件。

## 命名规范

- 界面/组件文档文件名 = 代码类名（与 FGUI 组件名一致，如 `BoxKaWuXingMahMainView.md`）
- 文档标题用中文名 + 类名，如 `# 主界面（BoxKaWuXingMahMainView）`
- 中文别名的确定：优先取代码注释里的叫法（如"游戏各种按钮相关界面"），没有则按功能命名（选漂界面、买马界面等）

## 交叉引用规范

- 界面文档 ↔ 组件文档：相对链接 `../组件/Xxx.md`
- 汇总文档 → 界面文档：相对链接 `界面/Xxx.md`
- 所有链接必须双向可达：模块分析能到每个界面/组件，界面/组件能回到模块分析

## 信息提取来源（数据源映射）

| 文档字段 | 提取来源 |
|---|---|
| 界面清单、包依赖、层级 | 代码 `@FguiView({name, layer, packages, sortingOrder})` 装饰器 |
| 界面/组件结构 | FGUI 工程对应包的 `package.xml` + 组件 XML（KW_ 前缀节点） |
| 按钮交互 | 代码 `addClick(btn, handler)` 调用 |
| 内部事件监听 | 代码 `@gf.listen(Event)` 装饰器 |
| 内部事件派发 | 代码 `dispatch(Event)` 调用 |
| 界面跳转 | 代码 `pfbm.uiFgui("Xxx").showFgui()/hideFgui()` |
| 网络收事件 | `protocol/gameCmd/` 各 Cmd 类的 `dealData`（含 dispatch 到哪个 GameEvent） |
| 网络发事件 | Controller（`control/`）的 sendXxx 方法 |
| 断线重连恢复 | `protocol/recoverCmd/` 各 RelinkOnXxxCmd |
| 状态字段 | 界面/组件类的成员变量 + `data/` 下 GameData 字段 |
| 交互边界规则 | 代码注释（该工程注释密度高，注释即规则来源） |
