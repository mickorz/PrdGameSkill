# Decision Workbench 中栏布局与内容整理（现状分析 + 调整建议）

> 日期：2026-11-09 | 对象：三栏式工作台的中间栏（QuestionDetail.tsx）
> 背景：用户反馈中栏「太不清晰，需要调整」，本文档先忠实整理现状，再给出问题清单与调整方案，供确认后实施。

### 各块数据来源

| 块 | 数据 | 接口/字段 |
|---|---|---|
| 标题区 | OQ id / severity / status | GET /api/state → questions[] |
| 大标题 + 问题描述 | 同一个 question 字段，渲染两遍 | questions[].question |
| 关联条目行 | requirement_id + 条目名 | /api/evidence 的 requirement.name |
| 原文引用 | 全部锚点 | /api/evidence → anchors[]（source-map.json 锚定行） |
| 裁决表单 | 动作/口径/理由 | 本地 draft state，草稿 800ms 防抖落盘 |
| 裁决历史 | 该问题的全部裁决 | decisions[] 过滤 |

## 二、问题清单（按影响排序）

| # | 问题 | 影响 | 严重度 |
|---|---|---|---|
| P1 | **内容重复**：大标题与「问题描述」块渲染同一个 question 字段，占两屏位置 | 长问题（如 OQ-003 三行）滚动距离翻倍，视觉噪音 | 高 |
| P2 | **「采纳当前口径」没有口径可看**：采纳的对象是 IR 现行口径（requirement.description / 现行规则），但中栏只有原文 PRD 引用，IR 口径只在右栏展示 | 裁决者无法就地确认「我同意的到底是什么」，要左右栏来回对照 | 高 |
| P3 | **缺少「AI 分析/推荐方案」层**：设计文档要求「问题描述 / 原始需求依据 / AI 分析（仅供参考）」三层，现状把三者压成了一个 question 字段 | 无法区分「事实描述」与「AI 倾向」，违背「AI 可提推荐但不能默认当答案」的设计原则 | 高 |
| P4 | **裁决动作无步骤感**：三个环节（看依据 → 选动作 → 填理由提交）没有编号与视觉引导，四按钮 2x2 平铺 | 新用户不知道先看哪里、后做什么 | 中 |
| P5 | **提交按钮禁用无解释**：理由没填时按钮置灰但不说明为什么 | 用户误以为页面坏了（本次 DEC-001 报错即由此而来） | 中 |
| P6 | **证据块不可折叠**：多锚点或长引用时把裁决表单推得很远 | 关键操作被淹没 | 中 |
| P7 | **裁决历史默认平铺**：翻案场景下历史是重要上下文，但当前位置太深且无折叠 | 翻案时看不到「当前有效版本」的对比 | 低 |
| P8 | **状态徽标语义弱**：标题区仅显示「已裁决：approved」英文枚举 | 与左栏「已确认/已否决/已挂起」中文术语不一致 | 低 |

## 三、调整方案（建议目标布局）

核心思路：**按裁决者的自然动线分三步**（问题是什么 → 依据是什么 → 怎么裁），每步有编号标题；消除重复；把「采纳对象」就地展示。

```
+----------------------------------------------------------+
| [HIGH] OQ-001   状态:待裁决        关联条目: GAME-RULE-003  |  ← 单行头部，术语与左栏一致
|                                                          |
| 第 1 步 · 问题是什么                                       |
|   默认值「房主庄」依据为创房面板实拍，需求正文仅记...          |  ← 唯一一次渲染 question（大字号）
|                                                          |
| 第 2 步 · 依据是什么                            [全部展开/收起]|
|   (1) IR 现行口径（=「采纳」的对象）                         |  ← 新增：evidence.requirement
|       +----------------------------------------------+   |     description + status
|       | 规则：默认房主为庄家   status: proposed        |   |     无描述时提示「IR 未登记，            |
|       +----------------------------------------------+   |      采纳前需补充口径」                  |
|   (2) 原始 PRD 引用                                        |
|       v source/01-基础规则.md · 1.2 庄家 · L28-38  [展开]   |  ← 锚点可折叠，默认展开第 1 个
|       | 原文行...                                         |
|                                                          |
| 第 3 步 · 人工裁决                                        |
|   裁决动作：                                              |
|   (o) 采纳当前口径   ( ) 修改为其他口径                     |  ← 改为竖排单选行，一行一个，
|   ( ) 否决           ( ) 挂起                             |     选中行右侧显示动作说明
|                                                          |
|   选中「采纳」→  显示默认理由（可改）                        |
|   选中「修改」→  + 最终口径 textarea（必填）                |
|   选中「否决/挂起」→ 理由必填                              |
|   裁决理由 [textarea]                                     |
|                                                          |
|   [ 提交正式裁决 ]  ← 禁用时旁边显示原因（如「请先填写理由」）  |
|   草稿已自动保存 12:33:45                                  |
|                                                          |
| 裁决历史（2）                                    [展开 v]  |  ← 默认收起；翻案时提示
|   最新有效: DEC-002 否决 ...                               |     「当前有效版本: DEC-002」
+----------------------------------------------------------+
```

### 分块要点

1. **头部单行化**：severity 徽标 + OQ id + 中文状态徽标（待裁决/已确认/已否决/已挂起）+ 关联条目 chip（悬停显示条目名，点击让右栏高亮对应卡片）。
2. **第 1 步**：只渲染一次 question，字号保持大标题级别；删除独立的「问题描述」块。
3. **第 2 步**新增「IR 现行口径」子块：
   - 数据已有（/api/evidence 的 requirement.description / status / authority），零后端改动；
   - 采纳动作的确认对象由此明确；description 为空时提示「该条目 IR 未登记口径，建议改用『修改』补齐后再采纳」——这本身就是一个质量钩子；
   - 原文锚点改为可折叠（默认展开第 1 个，其余收起），避免长引用把表单推走。
4. **第 3 步**：
   - 四动作从 2x2 网格改为竖排单选行（含动作说明小字），选中即显示对应动态字段；
   - 提交按钮禁用时，按钮旁直接显示原因文案（「请选择裁决动作」「请填写裁决理由」），不再让用户猜；
   - 「AI 分析（仅供参考）」若后续数据有推荐方案字段，插入第 2 步与第 3 步之间；当前数据无此字段，不虚构。
5. **裁决历史**默认折叠为一行（「裁决历史（2）· 当前有效：DEC-002 否决」），点击展开；只有存在历史时显示。

### 明确不改的部分

- 右栏影响分析、左栏列表、草稿自动保存与中断恢复机制（已验收，不在本次范围）。
- 裁决数据结构与 Schema（P6-A 产物，无变化）。
