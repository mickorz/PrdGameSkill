# report.md 解析字段被新增小节截断（范例丢失）

## 问题现象

workflow 版 report.md 的 PRD-005 详情块新增了 `**范例（需求必须按此格式写）**：` 小节（含 AC 表格），但生成的 Dashboard 里范例完全不显示。更隐蔽的是：抽查 JSON 里建议字段"看起来完整"（尾部是建议第 6 条"验收口径……"），误判为解析正常。

## 排查过程

1. 对比 report.md 原文与 report.json：原文中范例位于 `**建议**：` 与 `**处理状态**：` 之间，是独立小节。
2. 定位 parser 的字段正则：`**建议**：\s*([\s\S]*?)(?=\n\*\*|...)` —— 前瞻 `\n\*\*` 表示"遇到下一个 `**` 开头的行就停"。
3. 该前瞻原本假设建议之后紧跟 `**处理状态**：`（skill 版结构），workflow 版插入范例小节后，建议字段在范例标题处被截断，范例整段丢弃。

## 根因

字段提取正则的**结束条件写死了字段顺序假设**（建议之后必是处理状态），源文档在字段间插入新小节时静默截断，且截断结果自洽（尾部是完整句子），抽查不易发现。

## 解决方案

1. parser：建议字段改用专用提取——一路取到 `\n**处理状态**` 或块尾，中间的 `**范例**：` 等小节标题连同内容并入建议字段。
2. 模板 renderRich：`**xxx**：` 单独成行的渲染为加粗小节标题（虚线分块），连续 `|` 行转 HTML 表格，行内 `**bold**` 转 strong，多行逐行成段。
3. build-dashboard.example.mjs 补断言：范例标题/表格行/AC 编号必须在建议字段里，且处理状态不被吃入。

## 预防/注意事项

- 解析结构化 Markdown 时，字段结束条件不要假设"下一个同级标记"，应锚定**明确的下一个字段名**（如 `**处理状态**`）或块尾。
- 抽查解析结果时，不能只看"尾部是否完整"——截断自洽时会误判；应对源文档与产物做**关键词级**断言（如必须包含 AC-001），并把断言固化进 example 自检。
- 源文档新增小节类型时，先跑 example 双格式自检再重新生成产物。
