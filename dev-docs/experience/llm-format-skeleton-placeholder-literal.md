# STAGE_DOC_FORMAT 骨架占位被 LLM 当字面量写入终产物

## 问题现象

T5.1b 全量重跑（run-mwfb5d3r-7，2026-11-14）机械校验失败：`阶段文档 ST-C01 缺原子项 AT-ST-C01-001~008`（8 个全部）。人工查看文档发现结构完全正常，原子项内容齐全——只是原子标题写成了 `#### `{AT-ST-C01-001}` 首局随机坐庄`（ID 外多包了一层花括号）。

同 run 还出现两处同类问题：

- ST-C02 标题残留骨架指引：`## 术语与单位（有则填）`、`## 跨切面行为（无原子也列）`（骨架占位括号未去除）。
- ST-C05 正文残留生成过程说明行：`（以下按 JSON 中 features 顺序，每个功能点一节）`。

而首跑（2026-11-13）15 个阶段的 agent 全部正确去除占位符——同一 prompt、同一骨架，不同 run 的 agent 对占位说明的理解不稳定。

## 排查过程

1. 读 ST-C01 文档：原子项内容/字段全部正常，仅标题格式异常。
2. 对比首跑产物：首跑原子标题为 `#### `AT-ST-C01-001``（无花括号）——verify 正则 `/^#### `?(AT-[A-Za-z0-9-]+)/` 可匹配首跑格式，不匹配 `{AT-...}`。
3. 读 3-produce-outputs.js 的 `STAGE_DOC_FORMAT` 常量：骨架原文就是 `#### \`{AT-ST-Cxx-nnn}\` {原子项名}`、`## 术语与单位（有则填）`——花括号/括号是「占位说明」，骨架头部注明「花括号为占位说明不是要写出的内容」，但 LLM 不总是遵守。

## 根因

**骨架文本里的占位标记（花括号/指引括号/过程说明行）对 LLM 是弱约束**：prompt 里「花括号为占位说明」的声明写在骨架外部，模型注意力容易被骨架字面形态带偏，跨 run 表现不稳定（首跑 15/15 正确，重跑 3 处错误）。

## 解决方案

1. **终产物侧机械修复**（本次采用，产物已 99% 正确时成本最低）：node 正则替换
   - `#### `\{(AT-ST-C01-\d{3})\}` ` → `#### `$1` `（8 处）
   - `## 术语与单位（有则填）` → `## 术语与单位` 等（2 处）
   - 删生成说明整行（1 处）
2. **根治方向**（演进报告 v3 下一步建议 2）：骨架文本直接写干净形态（`#### \`{原子项 ID}\`` → 说明性占位不带花括号字面量），并把「括号指引/占位符必须去除」写进硬性规则列表（列表项约束力强于骨架外声明）。
3. 也可在 verify-output-spec 加「占位残留扫描」（搜 `（有则填）`/`（无原子也列）`/`{AT-ST-` 等模式），fail fast 拦在装配阶段。

## 预防/注意事项

1. 给 LLM 的格式骨架中，任何「看起来能直接抄」的字面文本都可能被照抄——占位说明优先用不可能出现在正文的标记（如 `<原子项ID>` 尖括号）或干脆分字段传 JSON 让模型自己组标题。
2. 机械校验正则要覆盖「标题行的 ID 形态」而不只内容（本次正则 `/^#### `?(AT-...)/ 恰好挡住了花括号变体，属幸运命中）。
3. PowerShell 里测试正则时注意反引号是转义字符——`node -e "..."` 双引号串里的反引号会被 PowerShell 吃掉导致测试正则失真（本次排查时旧文档匹配数误报 0），复杂正则验证一律写临时 .mjs 文件跑。
