## 四、遇到的问题与处理

### 1. subagent 并行结果被截断（影响最大）

现象：第一批 3 路并行返回合计约 82.5KB，输出在工具层被截断，A 组（01-14）完整、B 组部分可见、C 组（重连/小结算/总战绩/老PRD）结果全部丢失。

处理：重跑 B、C 两组，改为让 agent 把 JSON 写入临时文件（/tmp/prd-check-*.json），主控读文件，绕开对话通道的输出限制。代价：浪费一次三路并行（约 20 分钟）。

教训：多 agent 大结果一律落盘回传，不依赖对话输出。

### 2. 单上下文装不下全部材料

现象：需求 106KB + 规则 268KB，主控无法一次性读完做检查。

处理：按规则分组派 3 个并行 agent（各组自带需求全文），主控只做合并判断。副作用是跨组重复发现（见下条）。

### 3. 跨组重复发现需要人工去重

现象：66 条原始发现中，AI 缺失 3 组都报、杠补牌方向/庄标样式/昵称截断/财神染色等 2-3 组重复，且优先级判定不一（重连缺失一组 P2、一组 P1、一组 P0）。

处理：主控按主题聚类合并，同主题证据合并、优先级取多源共识（取较高者并复核理由），最终 45 条。此步骤无法脚本化（标题措辞不同），是人工成本最高的一步（约 10 分钟）。

### 4. Python 环境不可用

现象：`python3` 调用被 Windows Store 别名拦截（exit 49）。

处理：JSON 解析改用 node（仓库环境有 node）。后续本仓库工具脚本统一走 node。

### 5. 报告检查日期写错

现象：report.md 首版检查日期凭空写成 2026-02-14，实际执行日为 2026-11-10。

处理：git 时间戳复核后修正（随本报告一并提交）。教训：日期一律取系统时间，不凭记忆填写。

### 6. git add -A 混入并行会话产物

现象：最终提交把另一会话的本地配置与运行产物带入仓库：`.opencode-workflows/`、`.agents/skills/workflow-*`、`opencode.json(.bak)`、`tui.json(.bak)` 等 23 个文件中约半数与本任务无关。

处理：已推送不可回收，本次报告中登记。遗留：建议补 .gitignore（*.bak、.opencode-workflows/runs/、journal/ 等）并 git rm --cached 清理，待确认后执行。
