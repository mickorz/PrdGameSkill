## 2. 结构盘点结论

1. **文档组织成熟**：每份有「内容对照表」（章节 ↔ 原始材料映射），天然支持溯源；规则带变更标记（M4/M5/M6/M9/C4），番型带 ID（F01~F14/J01~J08/A01~A07/S0~S11）——可直接映射为 GAME-RULE ID 的原文锚点。
2. **规则集中度**：玩法规则集中在 01/02/03；数值与判定在 04/05/06；可配置项在 07；界面与交互在 08。
3. **变体声明**：多份文档提及「三变体差异」，需在抽取时锁定本样本为「卡五星（好友房）」变体，变体差异条目登记为 open question（本 v1 只实现好友房）。
4. **明显缺失 / 待确认章节**（初判，供审查报告引用）：
   - 02 游戏流程缺「二」章节（编号跳跃：一 → 三打漂），需核对是否刻意省略
   - 07 配置「九、十」章节编号缺失（八 → 十一）
   - 多人（非好友房）模式未在本样本内
5. **三场景 UI 对齐**：08 UI 交互覆盖对局桌面 / 结算界面 / 创房面板，与需求文档 8.2 节三场景（大厅 / 对局 / 结算）基本对齐；「游戏大厅」（房间列表）在 07 创房面板部分覆盖，房间列表页本身未见独立描述 → open question。

## 3. 对 IR 设计的输入（供抽取引用）

1. ID 分段建议（并行抽取防冲突）：基础+流程 RULE-001~030 / 操作 RULE-031~070 / 番型 RULE-071~100 / 胡牌结算 RULE-101~130 / 配置 CFG-001~040 / UI-001~010 + COMP-001~030 + EVENT-001~020 / FR 分属操作与 UI 段。
2. 番型 ID（F01 等）与结算步骤（S0~S11）直接写入 business_rules 文本，保留原文 ID 便于对照。
3. 状态机候选：全局对局状态（未开局 → 创建房间 → 打漂 → 定庄 → 发牌 → 行牌 → 和牌结算 / 荒庄 → 续局）。
4. 变体锁定：所有条目 name/description 前缀「卡五星（好友房）」语境；变体差异一律 open。
