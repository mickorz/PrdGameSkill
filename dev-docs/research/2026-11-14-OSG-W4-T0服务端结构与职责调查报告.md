## 3. 配置与生效链（作用域判定的依据）

### 3.1 两条配置加载路径

`hzmj_server/game_logic.cpp`：

- `LoadBoxJsonConfig()`（L17 起）：**好友房** JSON 覆写，注释「需求 §2 全部 19 项配置字段」。本轮已确认的字段包括：`base_score`、`first_banker_type`（0随机/1房主）、`rotate_banker_type`（0赢家坐庄/1逆时针轮换）、`draw_continue_banker`、`cai_shen_type`（**0白板财神/1翻财神**）、`banker_level_type`（0平庄起/1笃二老庄/2笃三老庄）、`enable_banker_discard_hu`（庄闲放铳）等。
- `LoadGoldJsonConfig()`（L208 起）：金币房路径（game_rule 读取），独立于好友房。

### 3.2 生效链模型（每个规则四段）

```
好友房 JSON 配置（LoadBoxJsonConfig 写入 ServerConfig）
  → 规则选择条件（如 GetFirstBankerType()==1 ? 房主 : 随机）
  → 调用链（common_game_init.cpp 注册 Step 链：ZhuangStep → ChipStep(骰子) → BoxJokerStep(定财神) → …，见 L148-169）
  → 运行期生效（ServerData 状态：SetZhuang/SetCaiShen/SetBankerLevel…）
```

### 3.3 对三个目标 Stage 的直接影响（先记录，不下结论）

| 现象 | 事实 | 影响的原子 |
|---|---|---|
| 「首局随机定庄」是配置项不是硬规则 | `first_banker_type` 好友房可配 0/1，默认 0 | AT-ST-C01-001 |
| 「首庄三牢、固定 8 倍」依赖配置 | `banker_level_type` 默认 0（平庄起，level=1 → 倍率 2），配 2 才三牢 8 倍 | AT-ST-C01-006/007/008 |
| 「白板固定为财神」是默认值不是唯一值 | `cai_shen_type` 好友房默认 0（白板），可配 1（翻财神） | AT-ST-C02-004/005 |
| 「打出的白板财神不能吃碰杠」有服务端机制支撑 | BoxJokerStep 注册财神时移出吃碰杠候选 | AT-ST-C02-009/010/011 |
| 「吃仅限上家」服务端直证 | BoxChowStep::Judge L56 | AT-ST-C04-013 |
| AT-ST-C02-008（conflict）服务端侧部分一致 | 服务端移出候选（规则语义），客户端高亮（UI 语义）冲突独立成立 | 差异复核需两条腿分开判 |

## 4. 风险与未知项（S2 待查清单的输入）

1. common_game 是否被其他玩法变体（萧山/桐庐/淳安/绍兴2r）以不同配置复用——已确认共享代码，**各变体配置默认值是否一致未查**（影响 `not_applicable` 判定）。
2. `first_banker_type`/`cai_shen_type` 等 19 项配置的**好友房实际下发值**（创房默认面板）在服务端代码不可见——需客户端创房 UI 配置或后端配置平台核对（scope 判定 `configVerified` 的缺口）。
3. 操作优先级的完整裁决顺序（胡>碰/杠>吃的实现细节、多人碰杠座位排序）在框架 mah_frame，本轮只定位到 askid 机制，未逐行确认。
4. 牌墙组成（136 张构成）服务端初始化代码未展开（ST-C02-001/002/003 客户端侧已 consistent，服务端侧待 S2 补证）。
5. `rand()` 随机源的均匀性与可测试性（AT-ST-C01-001 的「随机」语义验证手段）。
