# 「过2」按钮出处分析（客户端 + FairyGUI）

> 分析对象：`spec-workflow/output-spec/核心流程杭州麻将好友房AI-策划版.md`
> 分析日期：2026-11-17
> 关键条目：「【过】与「过2」同时出现时最右侧是「过2」」「过上行放弃；过2只在本地收起按钮并清掉本次压暗，再按禁手重新压暗，不上行」

## 结论

PRD 里的「过2」来自**客户端杭州麻将代码**与 **FairyGUI `box_hzmj_main` 包**，三处证据链：

1. 客户端权限位掩码定义了两个「过」位（`POWER_ID_CANCEL_C` / `POWER_ID_CANCEL_S`）；
2. 客户端视图层把两个位分别绑到「过」「过2」两个按钮，行为一上行一本地；
3. FairyGUI `Handler.xml` 中「过2」（x=2528）排在「过」（x=2338）右侧，是「最右侧是过2」的直接依据。

代码快照位置：`source-code/client/`（PrdGameSkill 仓库内）。

## 证据链

### 1. 权限位定义 — `Code/config/BoxMahDefine.ts`（L202-211）

```ts
public static PowerType: { [key: string]: number } = {
    POWER_ID_NONE: 0x0000,
    POWER_ID_CANCEL_C: 0x0001, // 过 1 (无需发回给服务端)  1 << 0
    POWER_ID_CANCEL_S: 0x0002, // 过 2 (需发回给服务端)    1 << 1
    POWER_ID_PLAY: 0x0004,     // 出
    POWER_ID_CHOW: 0x0008,     // 吃
    POWER_ID_PONG: 0x0010,     // 碰
    POWER_ID_HU: 0x0020,       // 和
    POWER_ID_KONG: 0x0040,     // 杠
    POWER_ID_WAIT: 0x0080,     // 听
    POWER_ID_REPLACE: 0x0100,  // 补
};
```

「过」类有两个独立权限位，这是「过2」概念的源头。

### 2. 按钮绑定与行为 — `Code/layer/BoxHzmjMainView.ts`

| 位置 | 内容 |
|---|---|
| L110 | `showGuo2: boolean` 字段 |
| L557-558 | `showGuo` 绑 **CANCEL_S**（需上报）、`showGuo2` 绑 **CANCEL_C**（仅本地） |
| L320 | `KW_BTN_Guo2.KW_Ani.skinName = "guo"` — 与「过」同一皮肤动画 |
| L569 | 调试日志直接输出「过2」文案 |
| L582 | `KW_BTN_Guo2.visible = powerState.showGuo2` |

点击行为：

- L1236 `onBtnGuo()`：调 `GameController.sendCancel()`（`gameController.ts` L453-463）→ 走 `GameGlcProtocol.ts` L164 的 `CS_CANCEL_C` 协议（注释「过C-->S」）**上行放弃**。
- L1246 `onBtnGuo2()`：仅本地收起按钮、清手牌灰态再按禁手重压，注释「本地取消操作按钮，**无需回包**；暗杠/碰吃等同回合场景」→ 对应 PRD「过2只在本地收起按钮…不上行」。

### 3. FairyGUI 布局 — `Fgui/assets/box_hzmj_main/component/Handler.xml`

操作按钮按 x 坐标从左到右固定排布，同属 group `n52_ev1d`，由控制器 `C_BtnState` page=2（碰杠胡页）控制显隐：

| 按钮 | 组件 id | x 坐标 |
|---|---|---|
| 吃 KW_BTN_Chi | n125_qy3a | 1250 |
| 碰 KW_BTN_Peng | n80_gv5d | 1440 |
| 杠 KW_BTN_Gang | n81_gv5d | 1630 |
| 胡 KW_BTN_Hu | n82_gv5d | 1820 |
| 报听 KW_BTN_Bao_Ting | n124_ptn1 | 2148 |
| 过 KW_BTN_Guo | n84_gv5d | 2338 |
| **过2 KW_BTN_Guo2** | n117_b2ev | **2528（最右）** |

两个过按钮都是同一个 `component/EffectBtn.xml`（150×150，内含 `KW_Ani` 主动画 + `KW_AniLight` 高亮动画两个 Loader3D，默认皮肤 `quxiao`，代码运行时替换为 `guo`）。因为共用同一皮肤动画，PRD 写「过和过2都显示『过』，玩家无法从外观区分」。

**x=2528 > x=2338**，即「过2」位于「过」右侧 190px 处 —— PRD「【过】与「过2」同时出现时最右侧是「过2」」的直接布局依据。

## 命名陷阱：枚举注释编号与按钮名相反

枚举注释的「过 1/过 2」编号与 UI 按钮名的「过/过2」**语义相反**：

| 口径 | 本地过（不上行） | 上行过（需上报） |
|---|---|---|
| 枚举注释（BoxMahDefine.ts） | 过 1 = CANCEL_C | 过 2 = CANCEL_S |
| 按钮实际绑定（BoxHzmjMainView.ts） | **过2** = CANCEL_C | **过** = CANCEL_S |

PRD 的行为描述（「过上行放弃；过2只在本地收起」）与**按钮绑定实现一致**，说明 PRD 取的是按钮名口径（`KW_BTN_Guo2` / `showGuo2` / `onBtnGuo2`），不是枚举注释的编号口径；`onBtnGuo2` 处较新的注释也确认了这个对应关系。

**写 PRD / 读代码时若按枚举注释口径理解，会把两个过的行为写反。**

## 排除项

- `E:/WorkProjects/fairygui`（autogen_fgui，血战麻将包）中无 Guo2/过2 相关内容，与杭州麻将无关，PRD 的「过2」不来自该仓库。
- `BoxHzmjTestView.ts` 的测试数据只发过 `POWER_ID_CANCEL_S`（只有「过」，无「过2」），不能作为过2场景依据。
