### PRD-001：大结算页展示与关闭后再打开规则缺失
- 优先级：P1
- 主题：大局结算
- 问题性质：描述不完整

**原文**（附录 A 后续版本配置（片数）、6.1.1 触发逻辑、6.1.2 UI交互以及说明）：
> 任一玩家结算后片数小于或等于 0 时结束本场并进入大结算

**问题**：缺少大结算页需求：触发条件（片数模式片数≤0 或后续配置）、页面内容（各小局得分明细与本场总分）、关闭方式（右上角关闭）、关闭后保留的【查看结算】入口及再次打开的数据一致性、【返回大厅】退出流程、重复点击与加载失败的兜底。

**影响**：大结算页无统一交互规则，关闭后无法再次打开或重复弹出，玩家无法复核本场分数，且无法判断该页在本期模式是否应出现。

**建议**：补充「大结算」章节：1) 触发：片数模式任一玩家片数≤0 结束本场，先播终局演出再打开大结算；本期 8 局模式不出现大结算，末局小结算底部仍为【返回大厅】；2) 内容：按小局列出每局各家得分，底部显示本场累计分与房号、日期时间；3) 交互：右上【×】关闭大结算返回房间或大厅，关闭后保留【查看结算】按钮，点击再次打开同一份大结算且数据与首次一致；【返回大厅】退出房间；4) 兜底：重复点击只保留一个实例；数据拉取失败显示「结算数据加载失败」与【重试】，不得出现空白页；5) 关闭与打开状态在本端本地保留，切后台返回后仍可按原状态查看。

**验收口径**：大结算页关闭后页面保留【查看结算】入口，点击可重新打开同一份大结算且各局明细与本场总分与首次一致；重复点击不产生多个实例；本期 8 局模式结束时直接显示末局小结算与【返回大厅】，不出现大结算入口；加载失败有明确提示与重试。

**关联缺陷**：
- 7153306612 【卡五星】【大局结算】关闭大局结算页，点击查看结算按钮，无法再次打开大局结算页

**处理状态**：待确认

### PRD-002：好友房回放功能需求缺失
- 优先级：P1
- 主题：回放
- 问题性质：需求缺失

**原文**（无（已检索：3 对局流程、4 局内流程、5 结算流程、6 结算界面、7.2 同步与异常处理、附录 A、附录 B 录屏素材））：
> PRD 中无对应描述。整体缺口为：PRD 未定义好友房回放的入口权限、回放态桌面规则、播放控制、详情可点性、结束态联动与异常兜底。

**问题**：PRD 未定义好友房回放：无回放入口与权限（参战玩家可看、从哪进入）、无回放态桌面规则（是否复用四人牌桌、哪些局内 UI 隐藏）、无播放控制（进度条、快进快退、暂停）、无回放内详情按钮可点性、无回放结束态与结算页联动规则。附录 B 仅为开发参考录屏清单，不构成功能需求。

**影响**：回放各端表现无统一验收口径，准备标记残留、快进丢选牌标签、详情不可点、播放结束回退但结算页残留等错误反复出现且无法判定对错。

**建议**：新增「好友房回放」章节：1) 入口与权限：对局结束后在小结算或战绩入口提供【回放】，仅本场参战玩家可见；2) 回放态桌面：复用四人牌桌与座位布局，隐藏准备标记、开始游戏与继续游戏按钮、操作按钮和倒计时，只读展示四家手牌、牌河、碰杠区、余牌与财神指示牌；3) 播放控制：进度条支持拖动、快进、快退、暂停，任意跳转后按目标时刻的服务端事件重建完整牌桌快照（含碰杠区、胡牌张、听牌与选牌标签）；4) 详情：回放内每个结算或胡牌条目的【详情】可点击，打开与对局一致的详情面板，关闭后回到原播放进度；5) 结束态：播放到末尾停在最后一帧并显示「回放结束」与【返回】，不得回退到起点；回放开始即关闭结算遮罩；6) 异常兜底：回放数据拉取失败显示「回放数据加载失败」并给【重试】【返回】，回放中切后台再返回按当前进度恢复。

**验收口径**：回放全程不显示准备标记、开始游戏与继续游戏按钮、操作按钮；拖动或快进到任意位置后牌桌、碰杠区、听牌与选牌标签完整重建；详情按钮可点击并能回到原进度；播放结束停在末帧且无结算页残留；加载失败有明确提示与重试入口。

**关联缺陷**：
- 7153077006 【卡五星】【回放】回放中一直显示已准备标记
- 7153309413 【卡五星】【回放】回放播放完毕后回退到起点，结算页未清除
- 7157529262 【卡五星】【回放】回放里的详情按钮需要可以点击
- 7157562594 【卡五星】【回放】回放中快进，选字标签就消失

### PRD-003：解散后切换房间时清理上一局结算层
- 优先级：P1
- 主题：结算／解散与切房
- 问题性质：描述不完整

**原文**（7.1 菜单（退出／确认解散）；7.2 同步与异常处理（重连恢复））：
> 服务端确认解散后，发起者返回大厅，其他玩家也返回大厅并显示「房间已解散」

**问题**：未规定解散后停留在房间、接受其他房间邀请并进入新房间时，必须关闭上一房间遗留的小结算面板、遮罩和长按查看牌桌预览，并清空其临时状态。

**影响**：旧结算界面会叠加在新房间桌面上，遮挡准备状态与开始游戏按钮；玩家可能误触【继续游戏】或【返回大厅】造成误操作，甚至影响新房间开局。

**建议**：在7.2补充：任意进入新房间（解散后留在房间被邀请、从大厅加入房间、重连到其他房间）的加载完成时，先关闭上一房间全部结算层（小结算面板、暗色遮罩、长按预览）并清空旧的牌桌快照；结算层未关闭前，禁止提交准备、开始游戏和出牌请求；若旧房间未解散且再次进入，则按7.2恢复其结算页。

**验收口径**：解散后留在房间，收到其他房间邀请并同意，进入新房间后只显示新房间的准备界面，无旧结算面板、遮罩或旧名次分数；若回到未解散的旧房间，仍能正确恢复该局结算页。

**关联缺陷**：
- 7146446371 【卡五星】好友房解散并留在房间内时，收到其他进房邀请并同意，进入新房间后行上局的结算界面未消失

**处理状态**：待确认

### PRD-004：少人局发牌后余牌数扣减规则未定义
- 优先级：P1
- 主题：行牌
- 问题性质：描述不完整

**原文**（3.3.2 玩法信息·剩余张数；4.4 发牌）：
> 本期初始显示136。首批起手牌背出现时一次更新为83，发牌翻牌和理牌期间保持83。

**问题**：未定义2人/3人局每人起手张数、庄家额外张数及对应余牌数计算公式，也未写明「余牌数=牌组总数−已发手牌总数」的通用口径，仅在四人局给出83这一具体值。

**影响**：少人局开局余牌数显示偏大，导致「杠前剩余可摸牌≥22」「余牌减至20判流局」等判断使用错误基数，影响杠牌与流局时机。

**建议**：在3.3.2「剩余张数」补充通用口径：余牌数初始值=本局牌组总数，首批起手牌背出现时一次性刷新为「牌组总数−已发手牌总数」，其中已发手牌按3.4发牌模块在对应人数下的起手张数取（四人局为4×13+庄家1=53，显示83）；之后常规摸1张减1、每杠减2；切换人数配置时重新计算初始值；断线重连以服务端下发的余牌数覆盖本端显示。

**验收口径**：任意人数开局后，余牌数等于牌组总数减已发手牌总数，且与牌墙实际剩余一致；杠牌校验与流局判定使用同一数值。

**关联缺陷**：
- 7143076059 【卡五星】剩余牌没有扣除已发手牌

**处理状态**：待确认

## 4. 总体建议

- **缺口最集中的模块**：模块分布第一名是「小结算详情」，共 3 条，对应 PRD 缺口为 PRD-012（小结算缺少胡分详情展示规范）、PRD-013（小结算缺少结算明细面板的倍数展示规范）、PRD-014（小结算缺少结算明细面板的条目清单）；其次是「桌面」3 条（PRD-016、PRD-017、PRD-018），「番型」与「小结算」各 2 条（PRD-006、PRD-007 与 PRD-010、PRD-011）。小结算详情的问题呈现为同一条链路（详情入口、条目清单、倍数展示、长内容排布）连续缺规格，属于结构性问题而非零散遗漏。
- **可能影响开发的问题**：P0 为 0 条，P1 共 5 条。其中 PRD-001（大结算页展示与关闭后再打开规则缺失）、PRD-003（解散后切换房间时未清理上一局结算层）、PRD-005（再来一局与继续游戏缺少加载和失败兜底）直接作用于结算层与状态复位链路，一旦按现状开发，容易出现结算页重复叠加、旧局数据串入新局，存在结算分展示错误与资损风险；PRD-004（少人局发牌后余牌数扣减规则未定义）影响余牌数与听牌剩余张数的计算口径，会影响「剩余张数」这一对玩家可见的计分相关提示；PRD-002（好友房回放功能需求缺失）在本 PRD 中完全无对应章节，若产品确认需要，则属于功能级缺失。
- **是否建议进入下一阶段规格生成**：建议进入，但需先闭合 P1。理由：无 P0 缺陷，P1 仅 5 条且集中在结算层复位、余牌计数、回放、再来一局兜底这几个局部环节，缺口边界清晰、可通过补写需求条款解决；19 条缺口中有 14 条为 P2，可在规格生成阶段并行补齐。建议在规格生成前置任务中先处理 PRD-001、PRD-003、PRD-004、PRD-005，避免结算与计数口径被固化进契约。
