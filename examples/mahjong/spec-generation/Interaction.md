## 全局交互原则

1. 事实优先：所有交互行为溯源 SRC-xxx；原文未定义的交互（超时默认值、失败提示、红点等）标「待确认」，不按常见竞品惯例补全。
2. 复用基准：整体布局复用杭麻好友房（SRC-709）、麻将子复用杭麻（SRC-750）、剩余张数复用杭麻（SRC-706）；本文只登记差异与显隐时机，不重复杭麻基准内部规格。
3. 动画时长刚性：全部动画时长按原文数值执行（总览见 SRC-704）；动画播放过程中有玩家离线、切后台等，不中断原本动画流程（SRC-737）。
4. 分工边界：玩法判定（何时可碰/杠/胡/亮倒、番型、算分、封顶公式）归 GDD；功能需求与验收归 PRD（本文可引 PRD-xxx 不展开）；本文只写界面表现、操作与反馈。
5. 按钮组结构统一：单操作为【主操作】+【过】置于玩家手牌右上方；多状态从左至右顺序为【碰】→【杠】→【亮】→【胡】/【自摸】→【过】（SRC-818）。
6. 反馈三分：动画反馈（碰杠胡/番型/亮倒动画）、文字反馈（toast/飘字/提示文案）、状态反馈（高亮/遮罩/标签/图标）。
7. 每操作可验收：每个主操作有 INT-xxx ID，供 Interaction-Contract.yaml 引用。

```

                            |
                  浏览/修改配置（单选、勾选、下拉）

                    勾选高分玩法 -> 卡五星*4/碰碰胡*4/杠上花炮*4(杠开)/三元七对*8 变灰且取消勾选

                            |
                点击[创建房间] --成功--> [牌桌主界面·等待入座]（页面 2）
```


1. 胡牌主链路：牌桌（页面 1~6）→ 有人胡牌：摊牌展示、「胡/自摸」文字、「对局结束」动画 1.3 秒（停留 0.5 秒）→ 买马判定：触发则买马弹窗（页面 7，INT-100，1.5 秒）→ 小结算（页面 8，INT-101~107）→ 非最后一小局点【继续游戏】（INT-106）→ 下一小局（对应 PRD 业务流程步骤 5 → 6a → 7 → 8）
2. 荒庄支线：牌摸完无人胡牌 → 摊牌、【荒庄】文字 1.3 秒 → 有未听牌玩家则「未听牌」飘字 + 查叫分数 + 「亮倒荒庄」赔付 → 小结算（页面 8）→ 最后一小局点【查看结算】（INT-105）→ 大结算（页面 9，INT-108）→ 离开路径复用杭麻（对应 PRD 业务流程步骤 6b → 7 → 8；荒庄不买马，无页面 7）
3. 全局状态支线：对局任意环节玩家断线 → 全局状态表断线覆盖层（页面 11，图标 + 分秒计时，每次断线重新计时；动画不中断）→ 重连后覆盖层消失 → 对局在原状态继续 → 后续按链路 1 或 2 收敛到小结算/大结算（对应 PRD 异常场景 EX-01）
