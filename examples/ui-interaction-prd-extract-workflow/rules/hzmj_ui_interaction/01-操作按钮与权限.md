# 操作按钮与权限（客户端 UI 交互基准）

> 来源：input-ui/xuanwulobby/assets/42319 代码逆向，提取日期 2026-11-11。锚点格式：文件 → 方法。检查需求文档对操作按钮与权限相关交互的描述是否完整、与实现一致。

说明：本文件只收录"按钮 / 权限位 / 手牌出牌交互 / 置灰 / 操作区开合"范围内、在 42319 代码中可验证的界面事实。倒计时、方位盘、庄标、首出提示条见 07-桌面常驻元素；胡牌动画与结算链见 03-结算链与胡牌展示；托管惩罚与超时提示文案见 05-托管与超时（本文件只写托管对"操作区"的影响）。

## 一、权限位与权限消息

1. 操作的权限是一个 9 位位掩码，取值定义在客户端常量表里：0x0000 无、0x0001 过（无需发回服务端）、0x0002 过（需发回服务端）、0x0004 出、0x0008 吃、0x0010 碰、0x0020 胡、0x0040 杠、0x0080 听、0x0100 补。锚点：config/BoxMahDefine.ts → BoxMahDefine.PowerType。
2. 位掩码里有三位在本玩法没有任何按钮或界面消费："吃"0x0008（主界面既无吃按钮节点也无 onBtnChi 点击方法）、"听"0x0080（听牌按钮由听牌数据驱动，不看该位）、"补"0x0100（补花/换牌界面不存在）。服务端即使下发这三位，界面也不会出现对应按钮。命令表里同样保留了 CMD_JOKER（财神）、CMD_HU_S（单人和）、CMD_WAIT_ANIM、CMD_REPLACE_FIRST 等名字，但 42319 没有任何命令类注册处理它们（死代码，无消费方）；CMD_SCENE_IDLE 有注册类，但 xyid 映射与场景映射都不含空闲场景，永远不会被派发（死代码，无消费方）。锚点：config/BoxMahDefine.ts → PowerType；controller/cmd/CmdDefine.ts；controller/cmd/gameCmd/GameIdleCmd.ts；controller/gameController.ts → Hzmj_SVR_PUSH_CMD_BY_XYID / Hzmj_SCENE_HANDLER_BY_STATE；layer/BoxHzmjMainView.ts → _getPowerShowState / initSkin（无吃、听、补的按钮处理）。
3. 权限下行走固定的四步链：命令执行时先判断是否"重连补数据"（justUpdateData），再写数据、再刷界面；justUpdateData 为真时只写缓存，完全不触发按钮显隐、动画、倒计时。锚点：controller/cmd/gameCmd/GamePowerCmd.ts → execute。
4. 一次权限消息会写四份数据：当前权限位与当前权限玩家（setCurPower）、复盘用的座位权限缓存（setFuPanPower）、权限询问号 askid（setPowerAskid）、出牌步骤标记置真（setPlayCardStep(true)）。后续所有操作上行都带这个 askid。锚点：controller/cmd/gameCmd/GamePowerCmd.ts → _updatePowerData；data/GameData.ts → setCurPower / setFuPanPower / setPowerAskid。
5. 权限消息同时把可选组合按牌组标志拆成三份缓存：碰组合（CMF_PONG）、杠组合（CMF_MKONG / CMF_CKONG / CMF_TKONG）、吃组合（CMF_CHOW）；碰按钮固定取第 0 个碰组合，杠按钮按下标取杠组合。锚点：data/GameData.ts → setCurPower / getPungCombInfo / getKongCombInfo；layer/BoxHzmjMainView.ts → onBtnPeng / onBtnChooseGang。
6. 前置守卫：自己已经胡牌时收到权限消息，setCurPower 在写完权限位后立即返回，不刷新碰/杠/吃组合缓存；权限数据为 null（他人抓牌走的那条路）时，三份组合缓存会被清空。锚点：data/GameData.ts → setCurPower（`localSeat == SELF_LOCAL_SEAT && getIsHu(...)` 早退；`_playCombs = data?.combs` 后重建缓存）。
7. 自己权限的按钮可显示状态由六个布尔一次算出：可碰/可杠/可胡/可出牌/可过/可过2 分别等于对应位大于 0；其中"可出牌"额外要求自己尚未胡牌（已胡时出牌位被强制关闭），碰/杠/胡/过位不受已胡影响，仍按位显示。锚点：layer/BoxHzmjMainView.ts → _getPowerShowState。
8. 他人权限走"不显示任何按钮"的分支：setPower 判定座位不是自己后，直接收起操作区并返回，不解析位、不点亮按钮；同一时刻权限命令还会给非自己座位派发清灰事件。锚点：layer/BoxHzmjMainView.ts → setPower（`localSeat != SELF_LOCAL_SEAT` 直接 closeOperate）；controller/cmd/gameCmd/GamePowerCmd.ts → _updateSeatPowerView。
9. 他人抓牌是一条不弹按钮的权限旁路：抓牌命令把"当前权限玩家=抓牌人、权限=仅出牌(0x0004)"写进数据层（组合传 null，等于清空组合缓存），但不派发按钮显隐事件，因此自己的操作区与置灰保持原样，只有"最近一条权限"的判定值变成只有出牌位。锚点：controller/cmd/gameCmd/GameTakeCmd.ts → _updateTakeData；data/GameData.ts → setCurPower。
10. 复盘（回放）权限是另一条渲染路径：按人数映射把每个本地座位映射到界面下标（_0 到 _3），逐座位显示独立的碰/杠/胡/过按钮；复盘里"过"与"过2"合并成同一个过按钮（两个位任一为真就显示），不存在单独的过2按钮，也不切换主操作区页面。锚点：layer/BoxHzmjMainView.ts → setFupanPower。
11. 断线重连进入"行动"场景时，权限按钮不是重新计算出来的，而是把场景数据里的 power 原样再过一遍权限命令（等价于正常收到一条权限消息），随后用计时器剩余秒数补倒计时与头像框。锚点：controller/cmd/sceneCmd/SceneActionCmd.ts → execute / _recoverClock。
12. 复盘步骤回放时，权限按钮按座位缓存逐座位重放：遍历人数、取该座位缓存权限、逐个调用复盘权限渲染；权限缓存清空（clearFuPanPower）只清数据、不隐藏已经显示的复盘按钮。锚点：controller/cmd/RecoverGameSceneCmd.ts → _recoverPowerBtns；data/GameData.ts → getFuPanPower / clearFuPanPower。

## 二、按钮显隐与操作区开合

13. 自己操作区的按钮节点集合（42319 主界面包内实际存在的名字）：KW_BTN_Peng、KW_BTN_Gang、KW_BTN_Guo、KW_BTN_Guo2、KW_BTN_Hu、KW_BTN_Cancel（与选择多杠页配合的取消键）、KW_BTN_Bao_Ting；另有按座位编号的复盘副本 KW_BTN_Peng_0 到 _3、KW_BTN_Gang_0 到 _3、KW_BTN_Guo_0 到 _3、KW_BTN_Hu_0 到 _3 与分组 KW_BTN_PGs。包内没有吃按钮、亮牌按钮、独立自摸按钮、聊天按钮、换三张按钮节点。锚点：fgui_uideclare/box_hzmj_main/FGUI_box_hzmj_main_Handler.d.ts；fgui/box_hzmj_main/box_hzmj_main.bin（按钮名字符串）；layer/BoxHzmjMainView.ts → initSkin（仅初始化碰/杠/过/过2/取消/胡/报听）。
14. 收到自己权限后，五个按钮的可见性一次写完：可见性严格等于对应位（碰、杠、过、过2、胡），随后无论位值如何都会把报听按钮强制置为不可见；报听按钮在皮肤初始化时也已被置为不可见。报听整体已下线：报听权限/上行/结束三个协议类在协议文件里被整体注释，包内残留的报听角标与换三张提示节点没有任何显示逻辑。锚点：layer/BoxHzmjMainView.ts → _setPowerButtonsVisible / initSkin；protocol/GameGlcProtocol.ts（报听协议段注释）；fgui_uideclare/box_hzmj_main/FGUI_box_hzmj_main_HzmjMainComponent.d.ts → KW_ImgBaoTing_0..3 / KW_BaoTingZhong / KW_HuanTips。
15. 操作区页面控制器 C_BtnState 只有三处赋值：复位与收尾写 0、碰杠胡任一可显示写 3、进入选择多杠写 4；代码里没有任何地方写 5（报听选择页），因此"第 5 页"在现网不可达。锚点：layer/BoxHzmjMainView.ts → initUI / resetUI / onMsgStartGame / closeOperate / _updatePowerBtnState / showChooseGang。
16. 互斥规则：碰、杠、胡三个布尔只要有一个为真，操作区切到第 3 页；否则只在"当前正停在第 3 页"时退回第 0 页（避免误改其它页面）。锚点：layer/BoxHzmjMainView.ts → _updatePowerBtnState。
17. 边界：只有"过/过2"权限时操作区不切页（两个过位不参与第 3 页判定），此时过按钮虽然可见，但操作区仍停在第 0 页，不会进入碰杠胡的展示态。锚点：layer/BoxHzmjMainView.ts → _updatePowerBtnState / _setPowerButtonsVisible。
18. 手牌"能不能出"是一个独立开关：收到自己权限时把 canPutCard 设为"可出牌"布尔；收起操作区、托管、选择杠发送后、手牌打出后都会把它置为不可出牌；点"过"或"过2"不会改动它（保留本次权限到达时的出牌能力）。锚点：layer/BoxHzmjMainView.ts → setPower / closeOperate / onBtnChooseGang / onShowTrustee；layer/BoxHzmjPlayerHandCards.ts → playMah。
19. 权限按钮的亮相动画是"先播一次入场、再常亮"：把按钮动画节点的资源固定设为 ui://box_hzmj_main/Anniu、高亮节点设为 ui://box_hzmj_main/Anniu_tx1，播放 animation1 后接 animation2 循环；传 isLight=true 的按钮（碰、杠、胡）还会额外循环高亮灯，过与过2 只播一次入场不常亮。锚点：layer/BoxHzmjMainView.ts → onShowBtnAniLight / _showPowerButtonsLight / _updateHuPower。
20. 动画播放没有"按钮可见"前置判断：每次收到自己权限都会对五个按钮各调一次动画（包括本次不可见的按钮），隐藏节点同样被写入 spine 资源并启动播放，代码不区分可见性。锚点：layer/BoxHzmjMainView.ts → _showPowerButtonsLight。
21. 胡按钮内容是动态的：左侧显示"要胡的那张牌"的牌面图（按 hu_mah 取牌图），下方显示胡牌倍数文本（hu_point + "倍"），动作皮肤按胡牌类型切换——点炮胡与抢杠胡用 hu，其余（自摸类）用 zimo。锚点：layer/BoxHzmjMainView.ts → _updateHuPower / _getHuActionSkinName。
22. 胡按钮上的"封顶倍数"文本是恒隐藏的：权限刷新时每次都会把 KW_HuPaiBeiShuFengDing 置为不可见，全文件没有把它置为可见的代码，因此界面只显示实际倍数，不显示封顶提示。锚点：layer/BoxHzmjMainView.ts → _updateHuPower。
23. 收起操作区是一次复合动作：操作区页面归 0、清复盘按钮（仅复盘模式生效）、手牌 canPutCard 置不可出、清文字提示、隐藏庄/闲提示条；末尾"自己已胡则清灰"这一分支实际不起作用——onClearGray 内部第一句就是"已胡直接 return"，等价于不清灰。锚点：layer/BoxHzmjMainView.ts → closeOperate / closeFupanOperate / onClearGray。
24. 收起操作区的触发点共九处：自己点击出牌（main view）、手牌组件内部自动出牌、碰回包、杠回包、多人和回包、结果胡回包、流局回包、他人权限到达、托管状态到达。锚点：layer/BoxHzmjMainView.ts → onPlayMah / setPower / onShowTrustee；layer/BoxHzmjPlayerHandCards.ts → playMah；controller/cmd/gameCmd/GamePungCmd.ts / GameKongCmd.ts / GameHuExCmd.ts / GameResultHuCmd.ts / GameDrawnCmd.ts → execute。
25. 边界：收起操作区发出的"清文字提示"不带强制参数，而提示层的清理逻辑在"当前正显示定时提示"时会直接忽略无参清理，因此"当前未过手，无法碰牌/无法吃胡"这类 1.3 秒定时提示不会被收起操作区提前抹掉，会自然倒计时消失。锚点：layer/BoxHzmjMainView.ts → closeOperate；layer/BoxHzmjTipAniView.ts → onClearTextTips / onShowTextTimeTips。

## 三、按钮行为与互斥

26. 按钮点击按命名约定绑定：界面节点的名字去掉 KW_BTN_ 前缀后按"下划线分词、首字母大写"拼成 onBtnXxx 方法名（KW_BTN_Peng → onBtnPeng、KW_BTN_Guo2 → onBtnGuo2、KW_BTN_Cancel → onBtnCancel、KW_BTN_Bao_Ting → onBtnBaoTing、KW_BTN_Xi_Pai → onBtnXiPai），框架在界面初始化时把同名的点击回调挂到节点上。锚点：assets/node_modules/kiwi/src/core/FguiView.ts → processBtnEvent。
27. 碰：固定取第 0 个碰组合，取不到就什么都不做（不发包、不关操作区、不清灰）；取到就上行碰请求，随后操作区归 0、清空置灰、取消托管。碰不隐藏首出庄/闲提示条。锚点：layer/BoxHzmjMainView.ts → onBtnPeng。
28. 杠：先看可杠组合个数——只有一个组合时直接按第 0 个发送杠请求；发送后手牌置为不可出、操作区归 0、隐藏庄/闲提示条、清空置灰、取消托管；组合取不到时直接返回，不发包且不改页面。锚点：layer/BoxHzmjMainView.ts → onBtnGang / onBtnChooseGang。
29. 多组合杠：可杠组合大于 1 时，点杠按钮不发送，而是切到选择杠页（第 4 页）显示取消按钮；杠牌选择列表在收到权限时就已经显示（列表项按可杠牌值渲染牌面与牌背），点某一项即按该项下标发送杠请求并收起。锚点：layer/BoxHzmjMainView.ts → onBtnGang / showMoreGang / showChooseGang / _updateGangPower。
30. 取消选择杠等价于"过"：点取消先退出选择杠页，再执行过按钮逻辑，即向服务端发送过请求并收起操作区。锚点：layer/BoxHzmjMainView.ts → onBtnCancel / onBtnGuo / showChooseGang。
31. 列表点击回调是"每次刷新权限都重复注册一次"的：showMoreGang 每次都调用 list.on(CLICK_ITEM)，全文件没有对应的 off，收到多次杠权限后同一个列表项会挂多份回调（每次点击会按份数重复执行选择与发送）。锚点：layer/BoxHzmjMainView.ts → showMoreGang。
32. 胡：点胡按钮先收起操作区，再上行胡请求，再隐藏庄/闲提示条，最后取消托管；没有"是否可胡"的二次校验，完全依赖权限位控制按钮可见性。锚点：layer/BoxHzmjMainView.ts → onBtnHu。
33. 现网没有独立的自摸按钮：主界面包里不存在 KW_BTN_Zimo 节点，自摸走胡按钮按胡牌类型切换 zimo 皮肤；代码里另有一个 onBtnZimo（只收起操作区、上行胡请求、取消托管，不隐藏庄/闲提示条），没有可绑定节点（死代码，无消费方）。锚点：layer/BoxHzmjMainView.ts → onBtnZimo / _getHuActionSkinName；fgui_uideclare/box_hzmj_main（无 Zimo 按钮声明）；fgui/box_hzmj_main/box_hzmj_main.bin（无 KW_BTN_Zimo 字符串）。
34. 两个过按钮分工不同：过按钮向上行发送过请求（携带 askid）、操作区归 0、清空置灰、取消托管；过2 按钮不发任何包，只在操作区处于第 3 页时把它归 0，随后"自己已胡则清灰"的分支同样被 onClearGray 的已胡守卫短路，等于什么也不做。锚点：layer/BoxHzmjMainView.ts → onBtnGuo / onBtnGuo2。
35. 边界：点过2 后手牌保持原来的置灰状态（既不清灰也不重算），直到下一条权限消息重新计算置灰；点过、碰、杠则会立刻清灰。锚点：layer/BoxHzmjMainView.ts → onBtnGuo2 / onBtnGuo / onBtnPeng / onBtnChooseGang。
36. 硬互斥：如果最近一条权限里带胡位、且操作区正停在第 3 页（碰杠胡展示态），任何出牌尝试都被拦截，并弹 3 秒文本提示"点“过”才能出牌"，必须先点过（或过2）退出展示态。锚点：layer/BoxHzmjMainView.ts → canPlayMahCheck。
37. 该互斥的判定值取自"全局最近一条权限"而不是自己的权限：他人抓牌会把数据层权限改写成仅出牌位，此后 getPower 不含胡位，互斥自然解除；因此该拦截只在"自己刚收到带胡权限且未处理"这段窗口内生效。锚点：layer/BoxHzmjMainView.ts → canPlayMahCheck（GameData.getPower）；controller/cmd/gameCmd/GameTakeCmd.ts → _updateTakeData。
38. 出牌上行字段固定为：座位=自己服务端座位、牌值、askid=最近一次权限询问号、flag=报听标记；报听标记在现网恒为 0，因为它的唯一来源"操作区第 5 页"没有任何赋值点（死分支）。锚点：layer/BoxHzmjMainView.ts → onPlayMah；controller/gameController.ts → sendPlay。
39. 上行不做 askid 有效性校验：askid 只从缓存读取，缺失时按 0 发送，客户端不会阻止提交。锚点：data/GameData.ts → getPowerAskid；controller/gameController.ts → sendPlay / sendCancel / sendHu / sendPung / sendKong。
40. 服务端拒绝操作的界面反馈（仅自己座位、非重连补数据）：未过手碰牌弹 1.3 秒"当前未过手，无法碰牌"，未过手吃胡弹 1.3 秒"当前未过手，无法吃胡"，手里没豆时弹 1.5 秒弹窗"手里没豆时，平胡不能被点炮"；"未过手吃"（第 4 号通知位）没有对应文案处理。锚点：controller/cmd/gameCmd/GameNotifyInfoCmd.ts → execute；config/GameDefine.ts → NotifyInfoFlag。
41. 每个权限按钮点击后并没有 0.5 秒防连点：文件里定义了 onDelayBtnTouchu（置 touchable=false 后延迟恢复），但全仓没有任何调用点，按钮可被连续点击重复上行（死代码，无消费方）。锚点：layer/BoxHzmjMainView.ts → onDelayBtnTouchu（仅定义）。

## 四、手牌交互

42. 单击出牌的前置守卫：若这张牌存在"打出后可听"的数据、自己尚未胡牌、且牌值不是 0，则单击出牌直接被拒绝（函数返回 false，不弹任何提示、不发送出牌包）；双击与滑动路径不经过这条拦截。锚点：layer/BoxHzmjMainView.ts → canPlayMahCheck（`state == WillPlayMahType.ONE_TOUCH` 分支）。
43. 提牌（把手牌抬起）会联动听牌弹窗：抬起的牌若命中"可听信息"，且自己未胡、牌值非 0，则直接弹出听牌列表窗（数据为该牌对应的听牌信息）；同一次操作还会把"桌面上与该牌同值的牌"高亮（放下牌时传 0 取消高亮）。锚点：layer/BoxHzmjMainView.ts → onUpDownMah；layer/BoxHzmjMah2DView.ts → showSpecialMah。
44. 自己出牌的收尾顺序固定：先派发"添加出牌"事件（飞到出牌区），再按上一次权限的 askid 上行出牌，最后统一收起操作区；出牌不会清置灰，也不会改按钮可见性，等下一次权限消息刷新。锚点：layer/BoxHzmjMainView.ts → onPlayMah；layer/BoxHzmjMah2DView.ts → addPlayMah。
45. 托管/自动托管触发的出牌走手牌组件内部的另一条路：当组件记录的"当前出牌牌值"为 0 时，播放出牌动画、按最新手牌数据重置、派发"收起操作区"与"添加出牌"，但不上行出牌包（该路径由服务端下发的出牌消息驱动，不是玩家点击）；记录值不为 0 时按"换牌"处理（重摆手牌或改河牌），不收起操作区。锚点：layer/BoxHzmjPlayerHandCards.ts → playMah。
46. 手牌可触摸性由两处共同决定：出牌能力开关 canPutCard（权限驱动）与组件自身的 canTouch / 每张牌的 touchable；自己胡牌时（结算设置胡牌表现）会把 canTouch 置为不可触摸，此后清灰接口因已胡守卫直接返回，手牌保持锁定。锚点：layer/BoxHzmjMah2DView.ts → setHu；layer/BoxHzmjMainView.ts → onClearGray / initSelfHand（canPlayMahCheck 回调注入）。
47. 长按手牌 0.3 秒打开记牌器的逻辑只写成回调：touchTick 判断"手牌被按住且未提起某张牌"累计 0.3 秒后打开记牌器弹层、松手关闭，但 42319 内没有任何调度或绑定调用点（死代码，无消费方）；现网的记牌器弹层由"记牌器道具使用成功"事件触发——道具使用成功后公共控制器派发点击记牌器事件，主界面收到后直接打开记牌器弹层。锚点：layer/BoxHzmjMainView.ts → touchTick / onClickCardCount；assets/common_game/controller/gamePropController.ts → _reqUseJpq。
48. 听牌按钮（KW_CompTing 内的"查听"按钮，位于主界面底部）显隐由多个检查入口驱动：出牌后按当前听牌数据决定显示或隐藏（显示时把 C_IsHu 切到"已听"页）、收到自己权限且带出牌位则隐藏、自己摸牌则隐藏、自己胡牌则隐藏、重连恢复时重新判定；此外结束游戏、重置、流局也会隐藏。锚点：layer/BoxHzmjMainView.ts → showTingPaiBtn / showTingBtn / checkShowTingBtnOnPlay / checkShowTingBtnOnPower / checkShowTingBtnOnTake / checkShowTingBtnOnSelfHu / checkShowTingBtnOnRecover / onGameEnd / resetUI。
49. 边界：点击查听按钮是"开/关"切换，打开时传入当前听牌数据；点桌面空白（手牌组件的外部点击回调）会关闭听牌窗。锚点：layer/BoxHzmjMainView.ts → onBtnTing / onTouchOther / initSelfHand。

## 五、手牌置灰

50. 置灰的触发条件只有"有碰或杠权限且没有胡权限"：既不满足碰/杠、或带胡位时，都会走清灰；满足时才根据组合挑一张"保留亮色"的牌，其余牌值全部置灰。锚点：layer/BoxHzmjMainView.ts → _updatePowerGray。
51. 保留亮色的牌按优先级确定：本次权限里有明杠组合（CMF_MKONG）且杠按钮可见时，保留明杠那张牌；否则有碰时保留第 0 个碰组合的第 0 张牌；两者都没有则清灰。锚点：layer/BoxHzmjMainView.ts → _updatePowerGray / _updateGangPower / _getGangPowerInfo。
52. 置灰按"牌值"而不是"牌的位置"：把当前手牌（含刚摸的那张）里除目标牌值以外的每个牌值放进灰表交给手牌组件，因此手里同牌值的多张牌会一起保持亮色、其它同值牌也不会被误灰。锚点：layer/BoxHzmjMainView.ts → _setHandGrayExcept；data/GameData.ts → getHandCards。
53. 清灰的触发点：点碰、点杠（选择成立）、点过、他人权限到达、托管状态到达。置灰只在收到置灰条件成立的新权限时重新建立；收起操作区里的清灰调用只在"自己已胡"时尝试，而该分支被已胡守卫短路，实际不会清灰；重置界面走的是清空手牌，灰表随牌一起消失（不是调用清灰接口）。锚点：layer/BoxHzmjMainView.ts → onBtnPeng / onBtnChooseGang / onBtnGuo / onClearGray / onShowTrustee / closeOperate / resetUI；controller/cmd/gameCmd/GamePowerCmd.ts → _updateSeatPowerView。
54. 已胡保护是硬前置：清灰接口第一句就是"自己已胡直接返回"，因此在已胡状态下无论是收起操作区、过2、还是他人权限到达触发的清灰都不会执行，灰表与触摸状态保持原样；恢复触摸（canTouch 与逐张 touchable 置真）也一并不执行。锚点：layer/BoxHzmjMainView.ts → onClearGray。
55. 除"权限驱动置灰"外还有一条单值置灰/清灰接口（setHandGray 监听 + 底层 setHandsGray），以及一条"按多张牌值保留、可选锁触摸"的批量接口（_setHandGrayExceptGroup），这两条在 42319 内都没有任何派发/调用点（死代码，无消费方）；需求文档若描述"某状态下整体置灰手牌"，不能以这两条为依据。锚点：layer/BoxHzmjMainView.ts → setHandGray / _setHandGrayExceptGroup；config/FguiViewDefine.ts → GameEventBoxHzmj.setHandGray。

## 六、托管与操作区联动

56. 托管（含自动托管）到达时对操作区的影响固定为：若正停在第 3 页则归 0、手牌置为不可出、清文字提示、未胡时清灰；不改变按钮可见性，等下一次权限消息重新刷。锚点：layer/BoxHzmjMainView.ts → onShowTrustee。
57. 托管状态的"空权限"自动触发：当收到自己权限但权限值为 0、且包厢处于托管状态时，自动走一次托管收起；碰、杠、结果胡三条回包里如果包厢处于托管状态，也会补一次托管收起。锚点：controller/cmd/gameCmd/GamePowerCmd.ts → _checkShowTrustee；controller/cmd/gameCmd/GamePungCmd.ts / GameKongCmd.ts / GameResultHuCmd.ts → execute。
58. 自动胡开关是一个复选按钮（C_Button：0/1，Check 模式）：点击后先在本地置"自动胡"标记，再按场景发托管请求（匹配场发匹配托管、包厢发自动托管类型）；再次点击仍会走同一方法再次请求自动托管，本地没有"点第二下取消自动胡"的分支——取消来自玩家状态通知（进入/退出托管、进入/退出自动托管）与重连恢复时的玩家托管标记，标记为关时同时把本地自动胡复位。锚点：layer/BoxHzmjMainView.ts → onBtnAutohu / _checkBotAutoBtn / onPlayerStateChange / checkShowTingBtnOnRecover。
59. 取消托管的调用点是自己主动操作的收尾：碰、杠、胡、过、出牌之后都会发一次"取消托管"请求，因此点任一操作按钮都会退出托管状态。锚点：layer/BoxHzmjMainView.ts → onBtnPeng / onBtnChooseGang / onBtnHu / onBtnGuo / onPlayMah → cancelAuto；controller/gameController.ts → sendPlay。
60. 做牌权限（非打牌权限位，独立字段 specfPower）会直接弹做牌界面：收到做牌权限或做牌数据时，只要权限值大于 0 就打开做牌弹层（按座位显示），界面上没有"做牌"入口按钮，正式对局中只能由服务端权限自动弹；测试面板由 T 键打开，正式环境（GameConfig.value 为 2）且非网页端时不响应 T 键，测试/预发环境或网页端可打开，面板内有做牌入口。锚点：controller/cmd/gameCmd/GameSpecfPowerCmd.ts / GameSpecfDataCmd.ts → execute；layer/BoxHzmjTestView.ts → onBtnSpecf；layer/BoxHzmjMainView.ts → _onKeyDown；assets/node_modules/kiwi/src/config/GameConfig.ts → value（正式环境返回 2）。
61. 做牌界面的按钮并非都做数量校验：确认做手牌会无条件上行；三种"摸牌方向"按钮只在已选牌数大于 0 时才发包，未选牌直接关闭界面不发包；"删墙"按钮没有数量判断（空选也会上行删墙请求）；确认并结束（onBtnConfirm2）会额外把本地做牌权限清零。锚点：layer/BoxHzmjSpecfView.ts → onBtnConfirm / onBtnTakeSoft / onBtnTakeHardasc / onBtnTakeHarddesc / onBtnDelwall / onBtnConfirm2。
62. 特殊权限事件监听（onMsgSpecfPower）是空实现：函数体内只有被注释掉的"显示作弊按钮"一行，且全仓没有任何派发方，作弊按钮因此永远不会出现（死代码，无消费方）。锚点：layer/BoxHzmjMainView.ts → onMsgSpecfPower；config/FguiViewDefine.ts → GameEventBoxHzmj.onMsgSpecfPower。
