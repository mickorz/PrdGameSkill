# 断线重连与场景恢复（客户端 UI 交互基准）

> 来源：input-ui/xuanwulobby/assets/42319 代码逆向，提取日期 2026-11-11。锚点格式：文件 → 方法。检查需求文档对断线重连与场景恢复相关交互的描述是否完整、与实现一致。

锚点路径约定：以 `42319/` 开头的锚点相对 `input-ui/xuanwulobby/assets/42319/`；以 `common_game/` 开头的锚点相对 `input-ui/xuanwulobby/assets/`；以 `node_modules/` 开头的锚点相对 `input-ui/xuanwulobby/assets/`。

## 一、重连入口与场景数据面

1. 断线重连的场景数据唯一入口是通用层 `respSceneData`：取下发包中的 `game_status` 作为 state、`scene_data` 作为原始字节，调用游戏控制器 `gameSceneBack(state, sceneData)`；state 为 0 时同样会调用。锚点：common_game/controller/tableController.ts → respSceneData()
2. state 只有 0 表示空闲（GAMESTATUS.kFree=0），大于 0 一律按局内处理：`TableData.setIsGameStart(state > 0)`，state>0 时启动局内安全监控 `startInGameMonitor()`。边界：10002（kSecurityDetect）与 10003（kRandomChair）也大于 0，同样被当作局内。锚点：42319/controller/gameController.ts → gameSceneBack()；node_modules/protocolLogicModule/src/lib/proto.d.ts → GameSceneResponse.GAMESTATUS
3. state 非 0 时先按服务端 `clock` 与 `time_pass` 设置"重连倒计时"（`ReportController.setRelinkClock`），把 `time_pass` 写入 `BoxRoomData.playerPassTime`，并触发安全中心 `onReconnect()`。锚点：common_game/controller/tableController.ts → respSceneData() / _checkSvrRelinkClock()
4. 记牌器在重连时用通用层缓存的 `CommonGameData.cardCounter` 重建（每出现一张计数 +1）；复盘模式下 `recoverCardCounter` 直接返回，不恢复。锚点：42319/controller/gameController.ts → gameSceneBack()；42319/data/GameData.ts → recoverCardCounter()
5. 每条普通下行推送都会先按包装体里的 `clock` 刷新公共倒计时（`ReportController.setClock`），再把 `playerPassTime` 归零；即重连后的剩余时间以"最近一条消息"为起点。锚点：common_game/controller/tableController.ts → respPushToClient() / _checkSvrClock()
6. 场景数据解析把 state 直接当消息 id 查解码表（`HzmjDataParser.parseGameMsg(state, sceneData)`），而解码表只登记消息 id、不登记状态值，解析结果恒为 null；因此"解析成功才派发 onResetUI + 执行状态恢复命令"的分支永不执行（死代码，见 04#74）。锚点：42319/controller/gameController.ts → gameSceneBack()；42319/protocol/GameGlcProtocol.ts → GAME_MSG_DECODERS
7. 因第 6 条，重连不会派发 `onResetUI`，牌桌界面保持进入游戏时的构建结果（`onResetUI` 的清场能力见 04#37、04#38）。锚点：42319/controller/gameController.ts → gameSceneBack()
8. 无论解析结果如何，重连后固定广播三项界面通知：`onIsGameStart(state > 0)`、`onIsGameStartPlayerPos(state > 0 || 当前局数 != 0)`、`onShowSelfPlayer(true)`（显示自己头像）。锚点：42319/controller/gameController.ts → gameSceneBack()
9. 自己头像位置由 `onIsGameStartPlayerPos` 决定：未开局用 `KW_POS_FREE`，已开局（或历史上已打过局）用 `KW_POS_GAME`；同时写入 `TableData.setPlayerHeadPos` 并通知 `onMeMoveHeadPos`。锚点：42319/layer/BoxHzmjPlayerView.ts → onIsGameStartPlayerPos()
10. 重连处理链的固定尾步是向服务端补发 GPS：`tableController.sendSelfGps(RoomData.getCurBoxId())`。锚点：42319/controller/gameController.ts → gameSceneBack()
11. 重连时若 `play_count > 0`（已在局中），会强制关闭一组准备/大厅类弹层：BoxRoomInfoView、GameQingshenCardView、GameLuckyComeCardView、BoxRoomHylbCardView、BoxShuffleCardView、RecommendCardFriendView。锚点：common_game/controller/tableController.ts → respSceneData()
12. 重连没有专用界面，完全按进入游戏时的加载清单重建：首屏 BoxHzmjBackView、BoxHzmjMah2DView、BoxHzmjMainView、BoxHzmjTipAniView，包厢再加 BoxHzmjPlayerView（匹配场用 BoxHzmjPlayerMatchView），延迟层再加载 BoxHzmjCardDownView 等；加载完成即重播背景音乐。锚点：42319/Game42319.ts → initUI()
13. 不存在"恢复中"抑制标志：`svrPushToClient` 默认 `justUpdateData=false`，重连后收到的首个普通下行消息仍按正常流程播放动画与音效；`GameData.setIsRelink` 只在发牌动画回调里被置 false、从未置 true（见 04#77）。锚点：42319/controller/gameController.ts → svrPushToClient()；42319/layer/BoxHzmjMainView.ts → onTakeFirstAniSelf()；42319/data/GameData.ts → setIsRelink()

## 二、重连后的倒计时、操作权与返回提示

14. 权限（操作权）消息驱动倒计时恢复：仅当 `ReportController.getClock() > 0` 时才广播 `setClock`、`onShowDeskCentLight`、`onShowPower(座位, true)` 三项；时钟为 0 或负数时三项 UI 都不刷新。锚点：42319/controller/cmd/gameCmd/GamePowerCmd.ts → _updatePowerClock()
15. 倒计时文本规则：复盘模式或时间大于 999 时整条忽略；时间大于 0 时每秒倒数，小于 10 补零显示，剩余 3 秒及以下换红色字体并在"是自己且未开启自动胡"时播放倒计时音效；时间等于 0 时固定显示 "00"；每次收到 setClock 先关闭操作引导浮层 GameBoxPropGuideView。锚点：42319/layer/BoxHzmjMah2DView.ts → setClock()
16. 桌面方位盘高亮同样受模式与时间约束：复盘模式或时间大于 999 时停止并忽略；否则只点亮当前操作座位的风向灯（其余熄灭），并按时间驱动闪烁。锚点：42319/layer/BoxHzmjMah2DView.ts → setDeskCentLight()
17. 他人长时间未操作会弹"操作引导"：倒计时经过 8 秒后，仅对非自己座位、且包厢已开局（`isStartBoxGame()`）时显示 GameBoxPropGuideView（带座位参数并置顶），每个倒计时周期只触发一次。锚点：42319/layer/BoxHzmjMah2DView.ts → setClock() / tipPlayerOperation()
18. 出牌超时预提醒弹层：非自己时，以 `playerPassTime` 与配置提醒时长的较大值作为已流逝时长，弹 BoxRoomTimeoutTipView（昵称、已流逝时长、超时解散时长），弹出后把 `playerPassTime` 归零；复盘模式下改为广播 `onNotifyBotHintTimeout`，不弹该窗。锚点：common_game/controller/cmd/NotifyPlayerActionCmd.ts → _playerBotHintTimeout()；common_game/controller/tableController.ts → respSceneData()
19. 玩家回桌提示：每条能解码出 seat 的下行都会检查该座位"有超时提醒且非掉线"，满足时隐藏 BoxRoomTimeoutTipView、弹 MessageSimpleBoxList 文案"玩家{昵称}已返回"（展示 3 秒、type 0）、广播 `onNotifyPlayerBackGame(座位)` 并清除超时标记。锚点：42319/controller/gameController.ts → svrPushToClient() / _playerBotHintTimeoutEnd()
20. 回桌提示的边界：消息里没有 seat（非 number）直接返回；`isWireBreak` 为真时整段跳过（掉线中不提示已返回）；仅自己座位额外广播 `onShowFanView`（番型/规则界面）。锚点：42319/controller/gameController.ts → _playerBotHintTimeoutEnd() / _decodeSeatForBotHint()
21. 他人头顶托管提示条在收到 `onNotifyPlayerBackGame` 时隐藏；自己（非复盘）收到该事件不处理。锚点：common_game/layer/component/BasicPlayerComp.ts → onNotifyPlayerBackGame()

## 三、断线重连场景命令链（sceneCmd）与可达性

22. 代码中存在"状态 → 恢复命令"映射表，仅登记 5 项：GAME_STATE_START→CMD_SCENE_START、GAME_STATE_SPECF→CMD_SCENE_SPECF、GAME_STATE_BANKER_TAKE→CMD_SCENE_TAKE_FIRST、GAME_STATE_ACTION→CMD_SCENE_ACTION、kGzmjStateMixCard→CMD_SCENE_MIX_CARD；表上注释明确其只是"占位标记（当前状态仅用于标识已识别；具体恢复逻辑在 cmd 内处理）"。锚点：42319/controller/gameController.ts → Hzmj_SCENE_HANDLER_BY_STATE
23. 该映射表唯一消费点在 `gameSceneBack` 的解析成功分支内，因解析恒为 null 而不可达；因此 5 个场景恢复命令、以及它们内部的重连时钟恢复与 end_wait 应答在当前构建中都不会被触发（死代码，见 04#74、04#75）。锚点：42319/controller/gameController.ts → gameSceneBack()
24. SceneActionCmd（动作阶段重连，不可达）的设计顺序为：先把出牌步骤置为进行中（`setPlayCardStep(true)`），再依次执行 START_GAME（静默）→ VS_PLAYER_INFO（静默）→ GAME_CONFIG → THROW_CHIP（静默）→ JU_DATA → RECOVER_WALL → RECOVER_HAND → RECOVER_OUTS → POWER，最后恢复时钟并处理 end_wait。锚点：42319/controller/cmd/sceneCmd/SceneActionCmd.ts → execute()
25. SceneStartCmd（开局重连，不可达）顺序为：START_GAME → VS_PLAYER_INFO（静默）→ GAME_CONFIG → END_WAIT，末尾调用 `GameData.initCardCounter()` 重建记牌器。锚点：42319/controller/cmd/sceneCmd/SceneStartCmd.ts → execute()
26. SceneTakeFirstCmd（发牌阶段重连，不可达）顺序为：START_GAME（静默）→ VS_PLAYER_INFO（静默）→ GAME_CONFIG → JU_DATA → THROW_CHIP（skipAni）→ RECOVER_WALL → RECOVER_HAND → end_wait 应答。锚点：42319/controller/cmd/sceneCmd/SceneTakeFirstCmd.ts → execute()
27. SceneSpecfCmd（做牌阶段重连，不可达）顺序为：START_GAME（静默）→ VS_PLAYER_INFO（静默）→ GAME_CONFIG → JU_DATA → THROW_CHIP（skipAni）→ RECOVER_WALL → SPECF_DATA → SPECF_POWER；body 为空时整条命令直接返回。锚点：42319/controller/cmd/sceneCmd/SceneSpecfCmd.ts → execute()
28. SceneMixCardCmd（洗牌阶段重连，不可达）顺序为：START_GAME（静默）→ VS_PLAYER_INFO（静默）→ GAME_CONFIG → JU_DATA → THROW_CHIP（skipAni）→ RECOVER_WALL → end_wait 应答。锚点：42319/controller/cmd/sceneCmd/SceneMixCardCmd.ts → execute()
29. 场景链恢复时钟的统一做法：目标座位取 `data.power.seat`（无 power 时为自己），并广播 `setClock(座位, clock)`、`onShowDeskCentLight(座位, clock + 1)`（比权限路径多加 1 秒）以及 `onShowPower(座位, true)`。锚点：42319/controller/cmd/sceneCmd/SceneActionCmd.ts → _recoverClock()
30. 场景链 end_wait 的统一做法：判空写作 `data.end_wait !== null`，`undefined` 同样进入分支，会以服务端 askid（缺失为 0）覆盖本地并立即上行 `sendEndWait`；`null` 时不上行。该实现重复出现在三条场景命令中。锚点：42319/controller/cmd/sceneCmd/SceneActionCmd.ts / SceneTakeFirstCmd.ts / SceneMixCardCmd.ts → _checkEndWait()
31. 场景报文与命令字段不匹配：MsgRelinkOnAction 实际只有 end_wait/start_game/ju_data/wall_mah/player_mah/power/joker 等字段，SceneActionCmd 读取的 vs_player_info、game_config、throw_chip 并不存在，对应子命令拿到 undefined 后各自 `if (!data) return` 直接返回；SceneStartCmd/SceneSpecfCmd/SceneTakeFirstCmd/SceneMixCardCmd 引用的 IMsgRelinkOnStart / IMsgRelinkOnSpecf / IMsgRelinkOnTakeFirst / MsgRelinkOnMixCard 在 proto 声明中不存在。锚点：42319/lib/proto_game_hzmj.d.ts → IMsgRelinkOnAction；42319/controller/cmd/sceneCmd/SceneActionCmd.ts → execute()

## 四、复盘式场景恢复：触发与恢复顺序

32. 当前唯一可执行的"按协议重放恢复场景"链路是复盘：批量数据 `dealBatchFupanData` 先广播 `onResetUI` 清场，再逐条以静默模式写入数据，最后以 headSign 执行 `CMD_FUPAN_RECOVER_GAME_SCENE` 统一渲染。锚点：42319/controller/gameController.ts → dealBatchFupanData()
33. 单步复盘 `dealMultipleFupanData` 会把主消息与 `adds` 合并后逐条写入（合并模式为静默）；若该步标记 `dealSeparate=true` 则不再统一执行场景恢复，由被合并步骤自身命令负责渲染，否则再用 `xy_sign`（缺省取主消息 id）触发场景恢复。锚点：42319/controller/gameController.ts → dealMultipleFupanData()
34. "静默写入"的语义是只更新数据缓存、不广播界面事件：`svrPushToClient(..., true)` 传入 type 为 "justUpdateData"，各消息命令（START_GAME、POWER、TAKE、PLAY_S、END_GAME、END_WAIT、GAME_CONFIG、JU_DATA、WAIT_INFO、RESULT_HU 等）都在数据写完后提前 return。锚点：42319/controller/gameController.ts → svrPushToClient()；42319/controller/cmd/gameCmd/*.ts → execute()
35. 场景恢复命令的前置守卫：body 为 null 直接返回；`justUpdateData === true` 时直接返回（"只写数据不渲染"）。当前两个调用方均未传该字段，这个提前返回分支在 42319 内无消费方（死分支，见 04#78）。锚点：42319/controller/cmd/RecoverGameSceneCmd.ts → execute()
36. 恢复链的两处无防御边界：RecoverHandsCmd 按 playCnt 直接索引 `player_mah[i]`，数组短于人数时会读到 undefined 并抛错；RecoverGameSceneCmd._recoverOuts 直接读取 `getPlayerCardsData(座位).riverCards`，牌数据缺失即抛错。锚点：42319/controller/cmd/helperCmd/RecoverHandsCmd.ts → execute()；42319/controller/cmd/RecoverGameSceneCmd.ts → _recoverOuts()
37. 清场顺序固定为"清场 → 写数据 → 渲染"：`onResetUI` 在主界面重置牌数据、操作面板、放大出牌、结果标识并关闭小结算；Mah2D 清空各座位手牌/河牌/胡牌/副露与牌墙、隐藏出牌箭头与桌面高亮、清空倒计时与两颗骰子、还原自己手牌位置与缩放；TipAni 隐藏开局动画/庄家提示/飘分/随机换座提示/碰杠胡动画/文本提示与动作标识，CardDown 隐藏胡牌与出牌落地图。锚点：42319/layer/BoxHzmjMainView.ts / BoxHzmjMah2DView.ts / BoxHzmjTipAniView.ts / BoxHzmjCardDownView.ts → resetUI()
38. `onResetUI` 会调用 `GameData.clearData()`：牌墙总数重置为 136（杭州麻将 108+16+12）、清空骰子、胡牌番种、最后一张牌、结算数据、复盘权限、记牌器等，因此恢复顺序必须是先清场再写数据。锚点：42319/layer/BoxHzmjMainView.ts → resetUI()；42319/data/GameData.ts → clearData()
39. headSign 为开局（GP_START_GAME）时按"发牌初始帧"恢复，顺序为：牌墙 → 骰子 → 手牌 → 庄家；此时不恢复河牌、不恢复复盘操作按钮、不恢复胡牌信息。锚点：42319/controller/cmd/RecoverGameSceneCmd.ts → execute()
40. 其他 headSign 走通用恢复，顺序为：牌墙 → 庄家 → 骰子 → 手牌 → 河牌 → 复盘操作按钮 → 胡牌信息。锚点：42319/controller/cmd/RecoverGameSceneCmd.ts → execute()
41. 复盘中的权限写入：权限消息在复盘模式只走"复盘按钮"分支——写入 `GameData.setFuPanPower` 并广播 `setFupanPower` 后立即返回，不刷新倒计时、不播提示、不处理听牌气泡。锚点：42319/controller/cmd/gameCmd/GamePowerCmd.ts → _updatePowerView()

## 五、各类元素的恢复表现

42. 牌墙恢复：先按包厢设置 `CommonGameData.getBoxCardwallOpen()` 决定牌墙显隐（`onShowWall`），再广播 `onMsgWallAppear`（按骰子与庄家重排实际牌墩），最后广播 `onUpdateMahCnt(剩余张数)` 刷新剩余牌数文本。锚点：42319/controller/cmd/RecoverGameSceneCmd.ts → _recoverWall()；42319/layer/BoxHzmjMah2DView.ts → onMsgWallAppear()；42319/layer/comp/BoxHzmjMahLeftComp.ts → updateMahCnt()
43. 牌墙"多一墩"的朝向由人数、骰子点数与庄家位置共同决定：2 人看骰子和奇偶，3/4 人结合庄家，最终把结果写入牌墙组件的 `severSeat` 与 `nMaxWallNum`（取 `GameData.maxWallNum`）后重建。锚点：42319/layer/BoxHzmjMah2DView.ts → onMsgWallAppear()
44. 骰子恢复：仅当 `GameData.getDice()` 长度为 2 时广播 `onShowDice(点数0, 点数1, true)`；skipAni=true 时两面播 "animation1" 且不安排自动隐藏，skipAni=false 时播 "animation" 并在 1 秒后隐藏。锚点：42319/controller/cmd/RecoverGameSceneCmd.ts → _recoverThrowChip()；42319/layer/BoxHzmjMah2DView.ts → showDice()
45. 手牌恢复的明暗参数：自己座位 `isShow=false`（组件置 CardState_Box.Stand，不摊开），其他座位 `isShow=true`（置 CardState_Box.Up，与摊牌 playHuEnd 使用的是同一状态值）；渲染时把摸牌并入牌组再重置整手牌与副露。锚点：42319/controller/cmd/RecoverGameSceneCmd.ts → _recoverHands()；42319/layer/BoxHzmjMah2DView.ts → setHandCard() / playHuEnd()
46. 自己手牌控件由 Mah2D 创建并注入 MainView（`initSelfHand` 传入 Mah2D 的 selfHand 实例），自己与三家手牌共用 Mah2D 的 `setHandCard` 监听；MainView 另有同名的无装饰器方法 `setHandCard(cards, state)`（死代码，见 04#80）。锚点：42319/layer/BoxHzmjMah2DView.ts → selfHand / initSelfHand 注入；42319/layer/BoxHzmjMainView.ts → setHandCard()
47. 河牌与出牌箭头恢复：逐座位重置河牌区；若存在"最后一张出牌"则按座位定位箭头，并在 showBig 为真时广播放大展示。锚点：42319/controller/cmd/RecoverGameSceneCmd.ts → _recoverOuts()
48. 出牌放大有双重守卫：放大对象仅限非自己座位，且必须开启"他人出牌放大"设置（`CommonGameData.getBoxShowBigOut()`），否则仅隐藏上一次放大图。锚点：42319/layer/BoxHzmjMainView.ts → showPutCardUi()
49. 庄家恢复：以 `GameData.getZhuangSeat()` 广播 `onShowZhuang`；玩家视图先隐藏全部座位的庄标识（C_Bank 置 "hide"）再把目标座位置 "show"，避免残留上一局庄标。锚点：42319/controller/cmd/RecoverGameSceneCmd.ts → _recoverZhuang()；42319/layer/BoxHzmjPlayerView.ts / BoxHzmjPlayerMatchView.ts → onShowZhuang()
50. 复盘操作按钮恢复：对 0..玩家人数-1 逐个读取 `getFuPanPower(座位)` 并广播 `setFupanPower`；界面按权限位显示 碰/杠/过/胡 四个按钮（POWER_ID_PLAY 且未胡时可出牌），任一动作按钮可见时显示按钮容器。锚点：42319/controller/cmd/RecoverGameSceneCmd.ts → _recoverPowerBtns()；42319/layer/BoxHzmjMainView.ts → setFupanPower()
51. 每次出牌都会清空复盘权限缓存，因此恢复出的复盘按钮只保留到下一次出牌前。锚点：42319/controller/cmd/gameCmd/GamePlayCmd.ts → _updatePlayData()
