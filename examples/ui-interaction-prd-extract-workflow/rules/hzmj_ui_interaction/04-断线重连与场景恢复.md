# 断线重连与场景恢复（客户端 UI 交互基准）

> 来源：input-ui/xuanwulobby/assets/42319 代码逆向，提取日期 2026-11-11。锚点格式：文件 → 方法。检查需求文档对断线重连与场景恢复相关交互的描述是否完整、与实现一致。

锚点路径约定：凡以 `42319/` 开头的锚点，均相对 `input-ui/xuanwulobby/assets/42319/`；以 `common_game/` 开头的锚点相对 `input-ui/xuanwulobby/assets/`。

## 一、重连入口与场景数据面

1. 断线重连的场景数据唯一入口是通用层 `respSceneData`：取下发包中的 `game_status` 作为 state、`scene_data` 作为原始字节，调用游戏控制器 `gameSceneBack(state, sceneData)`；state 为 0 时同样会调用。锚点：common_game/controller/tableController.ts → respSceneData()

2. state 非 0 时先按服务端 `clock` 与 `time_pass` 设置"重连倒计时"（ReportController.setRelinkClock），并把 `time_pass` 记入 `BoxRoomData.playerPassTime`，同时触发安全中心 `onReconnect()`。锚点：common_game/controller/tableController.ts → respSceneData() / _checkSvrRelinkClock()

3. 进入重连处理的第一件事是把游戏状态置为"已开局"：`TableData.setIsGameStart(state > 0)`；state>0 时启动游戏内安全监控 `startInGameMonitor()`。锚点：42319/controller/gameController.ts → gameSceneBack()

4. 记牌器在重连时用通用层缓存的 `CommonGameData.cardCounter` 重建；复盘模式下直接跳过重建（早期 return，不写数据）。锚点：42319/controller/gameController.ts → gameSceneBack()；42319/data/GameData.ts → recoverCardCounter()

5. 场景数据解析使用 state 值直接当消息 id 查解码表：`HzmjDataParser.parseGameMsg(state, sceneData)`。解码表只登记消息 id（769～2337 区间），未登记状态值，故解析结果恒为 null，后续"按状态执行恢复命令"的分支永不执行（死代码，无生效消费方，详见 04#64）。锚点：42319/controller/gameController.ts → gameSceneBack()；42319/protocol/GameGlcProtocol.ts → GAME_MSG_DECODERS

6. 由于解析恒为 null，重连时不会派发 `onResetUI`（该派发位于"解析成功"分支内），即断线重连不会重置牌桌界面数据，界面保持进入游戏时的初始构建结果。锚点：42319/controller/gameController.ts → gameSceneBack()

7. 无论解析结果如何，重连后都会无条件执行三项界面通知：`onIsGameStart(state > 0)`、`onIsGameStartPlayerPos(state > 0 || 当前局数 != 0)`、`onShowSelfPlayer(true)`（显示自己头像）。锚点：42319/controller/gameController.ts → gameSceneBack()

8. 自己头像位置由 `onIsGameStartPlayerPos` 决定：未开局用 `KW_POS_FREE`，已开局（或历史上已打过局）用 `KW_POS_GAME`；同时写入 `TableData.setPlayerHeadPos` 并通知 `onMeMoveHeadPos`。锚点：42319/layer/BoxHzmjPlayerView.ts → onIsGameStartPlayerPos()

9. 重连后还会向服务端补发 GPS：`tableController.sendSelfGps(RoomData.getCurBoxId())`，属于重连处理链的固定尾步。锚点：42319/controller/gameController.ts → gameSceneBack()

10. 重连时若 `play_count > 0`（已在局中），会强制关闭一组准备/大厅类弹层：BoxRoomInfoView、GameQingshenCardView、GameLuckyComeCardView、BoxRoomHylbCardView、BoxShuffleCardView、RecommendCardFriendView。锚点：common_game/controller/tableController.ts → respSceneData()

11. 重连后的界面集合没有"重连专用界面"，完全按进入游戏时的加载清单重建：首屏 BoxHzmjBackView、BoxHzmjMah2DView、BoxHzmjMainView、BoxHzmjTipAniView，包厢再加 BoxHzmjPlayerView（匹配场用 BoxHzmjPlayerMatchView），延迟层再加载 BoxHzmjCardDownView 等；加载完成即重播背景音乐。锚点：42319/Game42319.ts → initUI()

12. 重连后不存在"恢复中"抑制标志：`svrPushToClient` 默认 `justUpdateData=false`，重连后收到的首个普通下行消息仍按正常流程播放动画与音效；`GameData.setIsRelink` 仅在发牌动画回调里被置 false，从未被置 true（详见 04#67）。锚点：42319/controller/gameController.ts → svrPushToClient()；42319/layer/BoxHzmjMainView.ts → onTakeFirstAniSelf()；42319/data/GameData.ts → setIsRelink()

## 二、重连后的倒计时、操作权与返回提示

13. 操作权（权限）消息驱动倒计时恢复：仅当 `ReportController.getClock() > 0` 时才派发 `setClock`、`onShowDeskCentLight`、`onShowPower(座位, true)` 三者；时钟为 0 或负数时三项 UI 均不刷新（桌面不留残影）。锚点：42319/controller/cmd/gameCmd/GamePowerCmd.ts → _updatePowerClock()

14. 倒计时文本渲染规则：复盘模式或时间大于 999 点时整条消息被忽略；时间大于 0 时启动每秒倒计时，数字小于 10 补零显示，剩余 3 秒及以下换成红色字体、并在"是自己且未开启自动胡"时播放倒计时音效；时间等于 0 时固定显示 "00"；每次收到 setClock 先关闭"操作引导"浮层 GameBoxPropGuideView。锚点：42319/layer/BoxHzmjMah2DView.ts → setClock()

15. 桌面方位盘高亮同样受时间与模式约束：复盘模式或时间大于 999 时停止并忽略；否则点亮当前操作座位对应的风向灯，其余灯熄灭。锚点：42319/layer/BoxHzmjMah2DView.ts → setDeskCentLight()

16. 他人长时间未操作会弹出"操作引导"：倒计时经过 8 秒后仅对非自己座位、且包厢已开局（`isStartBoxGame()`）时显示 GameBoxPropGuideView（带座位参数并置顶），每个倒计时周期只触发一次。锚点：42319/layer/BoxHzmjMah2DView.ts → setClock() / tipPlayerOperation()

17. 出牌超时预提醒（离线/托管前提示）使用 `BoxRoomData.playerPassTime` 作为已流逝时长：若其小于配置的提醒时长则按配置值展示；弹窗 BoxRoomTimeoutTipView 携带玩家昵称、已流逝时长与"超时解散"时长；弹出后把 playerPassTime 归零。锚点：common_game/controller/cmd/NotifyPlayerActionCmd.ts → _playerBotHintTimeout()

18. 每次收到普通下行推送都会把 `playerPassTime` 归零（说明计时以"最近一次消息"为起点）。锚点：common_game/controller/tableController.ts → respPushToClient()

19. 玩家"超时未回"后重新产生动作时提示"已返回"：若该座位 `getTimeOutTip()` 为真且不是 `isWireBreak`，则隐藏 BoxRoomTimeoutTipView、弹 MessageSimpleBoxList 文案"玩家{昵称}已返回"（展示 3 秒、type 0）、派发 `onNotifyPlayerBackGame(座位)` 并清除超时标记。锚点：42319/controller/gameController.ts → _playerBotHintTimeoutEnd()

20. 上述"已返回"检查的边界：不满足"动作座位为自己"时不派发 `onShowFanView`（仅自己座位额外派发该事件）；`isWireBreak` 为真时整段提示跳过（断线中不提示已返回）；消息无法解码（parse 结果为 null）时直接 return，也不会触发。锚点：42319/controller/gameController.ts → _playerBotHintTimeoutEnd() / svrPushToClient()

## 三、断线重连场景命令链（sceneCmd）与其可达性

21. 代码中存在"状态 → 恢复命令"映射表，仅登记 5 项：GAME_STATE_START→CMD_SCENE_START、GAME_STATE_SPECF→CMD_SCENE_SPECF、GAME_STATE_BANKER_TAKE→CMD_SCENE_TAKE_FIRST、GAME_STATE_ACTION→CMD_SCENE_ACTION、kGzmjStateMixCard→CMD_SCENE_MIX_CARD；表上注释明确其只是"占位标记（当前状态仅用于标识）"。锚点：42319/controller/gameController.ts → Hzmj_SCENE_HANDLER_BY_STATE

22. 该映射表唯一消费点在 `gameSceneBack` 的解析成功分支内，因解析恒为 null 而不可达；因此 5 个场景恢复命令、以及它们内部的重连时钟恢复与 end_wait 应答在当前构建中都不会被触发（死代码，无生效消费方，详见 04#64、04#65）。锚点：42319/controller/gameController.ts → gameSceneBack()

23. SceneActionCmd（动作阶段重连，不可达）的设计顺序为：先把出牌步骤置为进行中（`setPlayCardStep(true)`），再依次执行 START_GAME（静默）→ VS_PLAYER_INFO（静默）→ GAME_CONFIG → THROW_CHIP（静默）→ JU_DATA → RECOVER_WALL → RECOVER_HAND → RECOVER_OUTS → POWER，最后恢复时钟并处理 end_wait。锚点：42319/controller/cmd/sceneCmd/SceneActionCmd.ts → execute()

24. SceneStartCmd（开局重连，不可达）顺序为：START_GAME → VS_PLAYER_INFO（静默）→ GAME_CONFIG → END_WAIT，末尾调用 `GameData.initCardCounter()` 重建记牌器。锚点：42319/controller/cmd/sceneCmd/SceneStartCmd.ts → execute()

25. SceneTakeFirstCmd（发牌阶段重连，不可达）顺序为：START_GAME（静默）→ VS_PLAYER_INFO（静默）→ GAME_CONFIG → JU_DATA → THROW_CHIP（skipAni）→ RECOVER_WALL → RECOVER_HAND → end_wait 应答。锚点：42319/controller/cmd/sceneCmd/SceneTakeFirstCmd.ts → execute()

26. SceneSpecfCmd（做牌阶段重连，不可达）顺序为：START_GAME（静默）→ VS_PLAYER_INFO（静默）→ GAME_CONFIG → JU_DATA → THROW_CHIP（skipAni）→ RECOVER_WALL → SPECF_DATA → SPECF_POWER；body 为空时整条命令直接返回。锚点：42319/controller/cmd/sceneCmd/SceneSpecfCmd.ts → execute()

27. SceneMixCardCmd（洗牌阶段重连，不可达）顺序为：START_GAME（静默）→ VS_PLAYER_INFO（静默）→ GAME_CONFIG → JU_DATA → THROW_CHIP（skipAni）→ RECOVER_WALL → end_wait 应答。锚点：42319/controller/cmd/sceneCmd/SceneMixCardCmd.ts → execute()

28. 场景链恢复时钟的统一做法：目标座位取 `data.power.seat`（无 power 时为自己），并派发 `setClock(座位, clock)`、`onShowDeskCentLight(座位, clock + 1)`（比 GamePowerCmd 多加 1 秒）以及 `onShowPower(座位, true)`。锚点：42319/controller/cmd/sceneCmd/SceneActionCmd.ts → _recoverClock()

29. 场景链 end_wait 的统一做法：只要 `end_wait` 非 null，就以服务端 askid 覆盖本地并立即上行 `sendEndWait`（不等玩家点击、不再走界面）；该行为在三条场景命令中重复实现。锚点：42319/controller/cmd/sceneCmd/SceneActionCmd.ts / SceneTakeFirstCmd.ts / SceneMixCardCmd.ts → _checkEndWait()

30. GameIdleCmd（空闲场景重连）会从 `men_feng` 中查找东风座位、换算本地座位并写入 `GameData.setMahDeskCentEast`，随后派发 `onShowDeskCentBg(座位)` 重置方位盘；但 42319 内没有任何执行点（死代码，无消费方，详见 04#65）。锚点：42319/controller/cmd/gameCmd/GameIdleCmd.ts → execute()

## 四、复盘式场景恢复：触发与恢复顺序

31. 当前唯一可执行的"按协议重放恢复场景"链路是复盘：批量数据 `dealBatchFupanData` 先派发 `onResetUI` 清场，再逐条以静默模式写入数据，最后以 headSign 执行 `CMD_FUPAN_RECOVER_GAME_SCENE` 统一渲染。锚点：42319/controller/gameController.ts → dealBatchFupanData()

32. 单步复盘 `dealMultipleFupanData` 会把主消息与 `adds` 合并后逐条写入（合并模式为静默）；若该步标记 `dealSeparate=true` 则不再统一执行场景恢复，由被合并步骤自身命令负责渲染，否则再用 `xy_sign`（缺省取主消息 id）触发场景恢复。锚点：42319/controller/gameController.ts → dealMultipleFupanData()

33. "静默写入"的语义是只更新数据缓存、不派发界面事件：`svrPushToClient(..., true)` 传入 type 为 "justUpdateData"，各消息命令（START_GAME、POWER、TAKE、PLAY_S、END_GAME、END_WAIT、GAME_CONFIG、JU_DATA、WAIT_INFO、RESULT_HU 等）都在数据写完后提前 return。锚点：42319/controller/gameController.ts → svrPushToClient()；42319/controller/cmd/gameCmd/*.ts → execute()

34. 场景恢复命令的前置守卫：body 为 null 直接返回；`justUpdateData === true` 时直接返回（"只写数据不渲染"）。当前两个调用方均未传该字段，这个提前返回分支在 42319 内无消费方（死分支，详见 04#68）。锚点：42319/controller/cmd/RecoverGameSceneCmd.ts → execute()

35. 复盘恢复前必须经过 `onResetUI` 清场（Reset 先于写入，否则会被清空）：MainView 侧清空牌数据、收起操作面板、隐藏放大出牌、清结果标识并关闭小结算界面；Mah2D 侧清空所有座位的手牌/河牌/胡牌/副露与牌墙、隐藏出牌箭头与桌面高亮、清空倒计时与两颗骰子、还原自己手牌的位置与缩放；TipAni 侧隐藏开局动画、庄家提示、飘分、随机换座提示与动作标识；CardDown 侧隐藏落地动画。锚点：42319/layer/BoxHzmjMainView.ts / BoxHzmjMah2DView.ts / BoxHzmjTipAniView.ts / BoxHzmjCardDownView.ts → resetUI()

36. `onResetUI` 会调用 `GameData.clearData()`，把牌墙总数重置为 136（杭州麻将 108+16+12）、清空骰子、清空胡牌番种/最后一张牌/结算数据/复盘权限等，因此恢复流程的顺序固定为"清场 → 写数据 → 渲染"。锚点：42319/layer/BoxHzmjMainView.ts → resetUI()；42319/data/GameData.ts → clearData()

37. headSign 为开局（GP_START_GAME）时按"发牌初始帧"恢复，顺序为：牌墙 → 骰子 → 手牌 → 庄家；此时不恢复河牌、不恢复复盘操作按钮、不恢复胡牌信息。锚点：42319/controller/cmd/RecoverGameSceneCmd.ts → execute()

38. 其他 headSign 走通用恢复，顺序为：牌墙 → 庄家 → 骰子 → 手牌 → 河牌 → 复盘操作按钮 → 胡牌信息。锚点：42319/controller/cmd/RecoverGameSceneCmd.ts → execute()

39. 复盘中的权限写入：权限消息在复盘模式只走"复盘按钮"分支——写入 `GameData.setFuPanPower` 并派发 `setFupanPower` 后立即返回，不刷新倒计时、不播提示、不处理听牌气泡。锚点：42319/controller/cmd/gameCmd/GamePowerCmd.ts → _updatePowerView()

## 五、各类元素的恢复表现

40. 牌墙恢复：先按包厢设置 `CommonGameData.getBoxCardwallOpen()` 决定牌墙显隐（`onShowWall`），再派发 `onMsgWallAppear`（按骰子与庄家重排实际牌墩），最后派发 `onUpdateMahCnt(剩余张数)` 刷新剩余牌数。锚点：42319/controller/cmd/RecoverGameSceneCmd.ts → _recoverWall()；42319/layer/BoxHzmjMah2DView.ts → onMsgWallAppear()；42319/layer/comp/BoxHzmjMahLeftComp.ts → updateMahCnt()

41. 牌墙"多一墩"的朝向由人数与骰子点数、庄家位置共同决定：2 人看骰子和奇偶、3/4 人结合庄家，最终把结果交给牌墙组件 `severSeat` 与 `nMaxWallNum`（取 GameData.maxWallNum）后重建。锚点：42319/layer/BoxHzmjMah2DView.ts → onMsgWallAppear()

42. 骰子恢复：仅当 `GameData.getDice()` 长度为 2 时才派发 `onShowDice(点数0, 点数1, true)`；第三参为 true 表示跳过骰子滚动动画、直接把两面停在结果点数上（恢复场景不播动画）。锚点：42319/controller/cmd/RecoverGameSceneCmd.ts → _recoverThrowChip()；42319/layer/BoxHzmjMah2DView.ts → showDice()

43. 手牌恢复的明暗规则：自己座位 `isShow=false`（手牌保持 CardState_Box.Stand，不摊开），其他座位 `isShow=true`（手牌摊开 CardState_Box.Up）；渲染时把摸牌并入牌组再重置整手牌与副露。锚点：42319/controller/cmd/RecoverGameSceneCmd.ts → _recoverHands()；42319/layer/BoxHzmjMah2DView.ts → setHandCard()

44. 自己手牌控件由 Mah2D 创建并注入 MainView（`initSelfHand`），且 `hands[0]` 就是该控件，因此恢复事件走 `setHandCard` 即可同时刷新自己与三家的手牌区；MainView 另有一个同名的无装饰器方法（死代码，详见 04#69）。锚点：42319/layer/BoxHzmjMah2DView.ts → initSelfHand 相关（selfHand 构造与注入）；42319/layer/BoxHzmjMainView.ts → setHandCard()

45. 河牌与出牌箭头恢复：逐座位重置河牌区；若存在"最后一张出牌"则按座位定位箭头，并在 showBig 为真时派发放大展示。锚点：42319/controller/cmd/RecoverGameSceneCmd.ts → _recoverOuts()

46. 出牌放大有双重守卫：放大对象仅限非自己座位，且必须开启"他人出牌放大"设置（`CommonGameData.getBoxShowBigOut()`），否则仅隐藏上一次放大图。锚点：42319/layer/BoxHzmjMainView.ts → showPutCardUi()

47. 庄家恢复：直接以 `GameData.getZhuangSeat()` 派发 `onShowZhuang`；PlayerView 先隐藏全部座位的庄标识（C_Bank 置 "hide"），再把目标座位置 "show"，避免残留上一局庄标。锚点：42319/controller/cmd/RecoverGameSceneCmd.ts → _recoverZhuang()；42319/layer/BoxHzmjPlayerView.ts → onShowZhuang()

48. 复盘操作按钮恢复：对 0..玩家人数-1 逐个读取 `getFuPanPower(座位)` 并派发 `setFupanPower`；界面按权限位显示 碰/杠/过/胡 四个按钮（POWER_ID_PLAY 且未胡时可出牌），任一动作按钮可见时显示按钮容器。锚点：42319/controller/cmd/RecoverGameSceneCmd.ts → _recoverPowerBtns()；42319/layer/BoxHzmjMainView.ts → setFupanPower()

49. 胡牌信息恢复：若存在结算数据（`getGuiYangResultData()`），以 type="replay" 执行 RESULT_HU；replay 分支只做"隐藏放大牌 → 修正抢杠副露 → 摊牌（playHuEnd）→ 显示台面标识"，不播放胡牌动画、不弹小结算/总结算。锚点：42319/controller/cmd/RecoverGameSceneCmd.ts → _recoverHuInfo()；42319/controller/cmd/gameCmd/GameResultHuCmd.ts → _updateHuView() / _tanPai()

50. 自己已胡时恢复会关闭出牌步骤：写入胡牌数据的过程中若胡牌座位是自己，调用 `TableData.setPlayCardStep(false)` 禁止继续出牌；摊牌时若自己是胡牌者，自己的手牌区会缩小并右移。锚点：42319/controller/cmd/gameCmd/GameResultHuCmd.ts → _updateHuData()；42319/layer/BoxHzmjMah2DView.ts → playHuEnd()

## 六、end_wait 应答

51. 收到 end_wait 的固定处理：先缓存 askid；若存在"发牌后待补发 end_wait"标记，则清除标记并立即上行 `sendEndWait` 后直接返回；`justUpdateData` 阶段到此为止不做任何界面表现（该命令本身没有界面分支）。锚点：42319/controller/cmd/gameCmd/GameEndWaitCmd.ts → execute()

52. "待补发"标记只在开局且当前局数不为 1 时置为 true，即非首局（跳过开局动画）由 end_wait 消息驱动自动应答；首局则走发牌动画结束回调主动上行。锚点：42319/controller/cmd/gameCmd/GameStartGameCmd.ts → execute()；42319/data/GameData.ts → setTakeFirstEndWait() / getTakeFirstEndWait()；42319/layer/BoxHzmjMainView.ts → onTakeFirstAniSelf()

53. 上行报文内容固定：seat 取自己座位（`getSelfSeat() || 0`）、type 固定 0、askid 取 `getEndWaitAskid()`（缺省 0），走 CS_END_WAIT 通道。锚点：42319/controller/gameController.ts → sendEndWait()；42319/data/GameData.ts → getEndWaitAskid()

54. 胡牌流程对 end_wait 做去重：一炮多响/多家胡时动画回调可能多次触发，`_sendEndWaitOnce` 保证同一批胡牌只上行一次；当前实现把"最后一次胡"视为恒真，于是在飘分步骤即提前上行，后面"非最后一次胡"分支为死分支。锚点：42319/controller/cmd/gameCmd/GameHuExCmd.ts → _playHuAnimations()
