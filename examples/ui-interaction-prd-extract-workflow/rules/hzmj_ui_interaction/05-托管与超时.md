# 托管与超时（客户端 UI 交互基准）
> 来源：input-ui/xuanwulobby/assets/42319 代码逆向，提取日期 2026-11-11。锚点格式：文件 → 方法。检查需求文档对托管与超时相关交互的描述是否完整、与实现一致。

## 一、托管与自动摸打的入口与状态回写

1. 自动摸打按钮是听牌组件内部的子节点（KW_CompTing.KW_BTN_AUTOHU），并非主操作区独立按钮；听牌组件隐藏时该入口一同消失。锚点：fgui_uideclare/box_hzmj_main/FGUI_box_hzmj_main_CompTing.d.ts → KW_BTN_AUTOHU；layer/BoxHzmjMainView.ts → showTingPaiBtn / showTingBtn。
2. 按钮为两态控件：C_Button.selectedIndex 为 0 表示未托管、1 表示托管中；按钮内部只有 C_Button 控制器与 bg 图，无独立文字。锚点：fgui_uideclare/box_hzmj_main/FGUI_box_hzmj_main_AutoHuBtn.d.ts → C_Button / bg；layer/BoxHzmjMainView.ts → _checkBotAutoBtn。
3. 听牌组件由 showTingPaiBtn 统一开关：自己有听牌数据且未胡牌时置 visible=true 并把 C_IsHu 置 1；听牌数据为空或自己已胡时置 visible=false。摸牌（checkShowTingBtnOnTake）、自己胡牌（checkShowTingBtnOnSelfHu）、小局结束（onGameEnd）无条件下隐藏；出牌后由 checkShowTingBtnOnPlay 按最新听牌数据决定显隐；自己拿到出牌权限时 checkShowTingBtnOnPower 也会隐藏。组件隐藏时自动摸打按钮随之消失。锚点：layer/BoxHzmjMainView.ts → showTingBtn / _refreshTingCompHuState / showTingPaiBtn / checkShowTingBtnOnTake / checkShowTingBtnOnSelfHu / checkShowTingBtnOnPower / onGameEnd。
4. 按钮点击按 KW_BTN_ 名称自动绑定到 onBtnAutohu（KW_BTN_ + 下划线分段首字母大写驼峰 → onBtn 前缀），不需要在视图里显式 addClick。锚点：layer/BoxHzmjMainView.ts → onBtnAutohu；node_modules/kiwi/src/core/FguiView.ts → processBtnEvent（`onBtn${...}` 绑定）。
5. 点击自动摸打先写本地标记再发包：onBtnAutohu 第一步执行 GameData.setAutoHu(true)，无二次确认、无前置可用性检查（不看房间规则、不看是否已托管）。锚点：layer/BoxHzmjMainView.ts → onBtnAutohu；data/GameData.ts → setAutoHu / _autoHu。
6. 非匹配场（金币场/好友房）点自动摸打发 kBotAuto：tableController.reqTrustee(RoomData.getCurBoxId(), box_logic_cli.BotRequest.TYPE.kBotAuto)。锚点：layer/BoxHzmjMainView.ts → onBtnAutohu；common_game/controller/tableController.ts → reqTrustee。
7. 匹配场点自动摸打发的是默认 kBot 而不是 kBotAuto：onBtnAutohu 调用 reqMatchTrust() 未传 type，默认值 kBot。因此匹配场"自动胡按钮"实际请求的是普通托管。锚点：layer/BoxHzmjMainView.ts → onBtnAutohu；common_game/controller/tableController.ts → reqMatchTrust（type 默认 kBot）。
8. reqMatchTrust 的两条前置守卫：非匹配场直接 return；未开局（TableData.getIsGameStart() == false）直接 return。此路径下 autoHu 已在点击时置 true，请求未发出也不会回滚（本地标记与服务端状态不一致）。锚点：common_game/controller/tableController.ts → reqMatchTrust；layer/BoxHzmjMainView.ts → onBtnAutohu。
9. reqTrustee 的前置守卫与类型归一：复盘模式直接 return；自己 isBot 时强制 trust=false 且 type=kBot；否则自己 isBotAuto 时强制 trust=false 且 type=kBotAuto；归一后 type 仍为 kInvalid 时直接 return。锚点：common_game/controller/tableController.ts → reqTrustee。
10. 因此"取消托管"在未托管时不产生请求：普通状态下 cancelAuto() 发 kInvalid 会被第 9 条丢弃；已托管（isBot 或 isBotAuto）时 kInvalid 被改写成对应类型的取消请求。锚点：layer/BoxHzmjMainView.ts → cancelAuto；common_game/controller/tableController.ts → reqTrustee。
11. 手动操作会取消托管：碰、选杠、自摸、胡、过都在发包之后调用 cancelAuto()，顺序固定为"先发操作包、再发取消托管包"。锚点：layer/BoxHzmjMainView.ts → onBtnPeng / onBtnChooseGang / onBtnZimo / onBtnHu / onBtnGuo（均调用 cancelAuto）。
12. 有两类操作不取消托管：主动出牌 onPlayMah 只发 sendPlay（是否报听由 C_BtnState == 5 决定）；"过2" onBtnGuo2 只把 C_BtnState 从 3 切回 0、已胡时清置灰，不发 sendCancel、不调 cancelAuto。锚点：layer/BoxHzmjMainView.ts → onPlayMah / onBtnGuo2。
13. 取消选择杠等于"过"：onBtnCancel 先 showChooseGang(false) 再 onBtnGuo，因此同样走 sendCancel + cancelAuto。锚点：layer/BoxHzmjMainView.ts → onBtnCancel / onBtnGuo。
14. 按钮选中态由自己座位的状态事件驱动：kBot、kBotAuto 置 1；kUnBot、kUnBotAuto 置 0；localSeat 不是自己时不处理。锚点：layer/BoxHzmjMainView.ts → onPlayerStateChange（@gf.listen GameCommonUIEventDefine.onPlayerStateChange）。
15. _checkBotAutoBtn 的写入是不对称的：置 1 时不回写 GameData.autoHu；仅在置 0 时执行 GameData.setAutoHu(false)。因此"服务端推来的托管态"不会让客户端进入静音倒计时的自动胡分支。锚点：layer/BoxHzmjMainView.ts → _checkBotAutoBtn。
16. 重连恢复按钮态：checkShowTingBtnOnRecover 调用 showTingBtn 后再用 self.isBot || self.isBotAuto 回写按钮选中态，手动托管与自动摸打都显示为选中；此路径同样不回写 autoHu。锚点：layer/BoxHzmjMainView.ts → checkShowTingBtnOnRecover。
17. 自动胡标记的三处复位：每小局开始 onGameStart 显式 setAutoHu(false)；resetUI 链路 GameData.clearData() 置 false；clearData 同时清空托管数组（_trustPlay）。锚点：layer/BoxHzmjMainView.ts → onGameStart / resetUI；data/GameData.ts → clearData。
18. 托管请求失败无界面反馈：响应仅比对 table_id 与 flag == kSuccess，失败只 console.error，不改托管标记、不弹提示、不关遮罩，按钮态停留在原状态。锚点：common_game/controller/cmd/RespPlayerBotCmd.ts → execute；common_game/controller/cmd/RespPlayerBotAutoCmd.ts → execute。
19. 托管请求成功统一做四件事：写 TableData 托管/自动摸打标记；bot=true 显示托管遮罩、bot=false 隐藏遮罩；取消时用服务器回传 clock 调 setUnBotClock 恢复倒计时；向自己派发 kBot/kUnBot 或 kBotAuto/kUnBotAuto。锚点：common_game/controller/cmd/RespPlayerBotCmd.ts / RespPlayerBotAutoCmd.ts → execute；common_game/controller/reportController.ts → setUnBotClock。
20. 取消托管后倒计时按剩余时间重算：onPlayerStateChange 中，(自己是当前权限玩家且 action 为 kUnBot) 或任意 kUnBotAuto 时，取 ReportController.getClock() 剩余秒数重新派发 setClock；剩余为 0 时不派发。锚点：layer/BoxHzmjMainView.ts → onPlayerStateChange；common_game/controller/reportController.ts → getClock / setUnBotClock。

## 二、托管遮罩与操作区收起

21. 托管遮罩是平台公共弹层 GamePopTrustView：Base 层、Ani 排序（盖在牌桌之上）、notLoading；initUI 把自身 touchable 置 true，并把蒙层节点 n2 设为 visible + touchable，形成全屏拦截点击的遮罩。锚点：common_game/layer/GamePopTrustView.ts → initUI；common_game/config/FuiCommonGameView.ts → GamePopTrustView。
22. 遮罩显示时机（手动托管）：自己收到 kBot 状态通知时显示；托管响应成功时也显示；重新进入游戏场景时若自己 isBot 或 isBotAuto 则补显示。锚点：common_game/controller/cmd/NotifyPlayerActionCmd.ts → _playerBot；common_game/controller/cmd/RespPlayerBotCmd.ts → execute；common_game/controller/tableController.ts → _checkPlayerBot。
23. 自动摸打的遮罩显示口径与其数据通知不一致：服务端推送 kBotAuto 的通知路径不弹遮罩（只写数据 + 触发举报检查）；但客户端主动请求的响应成功路径（RespPlayerBotAutoCmd）会弹遮罩。锚点：common_game/controller/cmd/NotifyPlayerActionCmd.ts → _playerBotAuto；common_game/controller/cmd/RespPlayerBotAutoCmd.ts → execute。
24. 好友房的托管遮罩被重映射：进好友房入口时把 GamePopTrustView 名称改为 GameBoxTrustView，因此好友房弹的是 GameBoxTrustView（蒙层由 C_Hide 控制），金币场仍是 GamePopTrustView。锚点：common_game/Game.ts → _initBoxRoomEntry。
25. 遮罩的取消托管按钮按房型走两条链路：匹配场调 cancelMatchTrust()；非匹配场调 GameInstController.inst.CardController?.sendMsgTrust(false)（CardController 为空时静默不发包）；若此时已不在游戏中则直接关界面。锚点：common_game/layer/GamePopTrustView.ts → onBtnCancel。
26. 42319 没有注册 CardController，也没有 sendMsgTrust 实现：Game42319.start 只注册 GameController 与 GameInstController.GameController。因此金币场遮罩上的"取消托管"按钮在本模块内没有请求链路，只能等其它状态变化把遮罩关掉。锚点：Game42319.ts → start；common_game/layer/GamePopTrustView.ts → onBtnCancel。
27. 好友房遮罩的取消按钮直接走托管取消：GameBoxTrustView.onBtnCancel → reqTrustee(boxid, kInvalid)，经第 9 条归一后才真正发出（仅在自己已托管时有请求）。锚点：common_game/layer/GameBoxTrustView.ts → onBtnCancel。
28. 遮罩内的"隐藏托管 UI 元素"分支在本玩法不生效：GamePopTrustView.onHideBoxRoomTrustViewElements 会把 C_Hide 置 1、自身 touchable 置 false、n2 隐藏，但 42319 全模块没有任何地方派发该事件（全仓仅 42309 派发）。锚点：common_game/layer/GamePopTrustView.ts → onHideBoxRoomTrustViewElements；42319 内检索无 onHideBoxRoomTrustViewElements 派发（死链路，无派发方）。
29. 进入托管时本家操作区立即收起：onShowTrustee 把操作面板 C_BtnState 切回 0 页、手牌 canPutCard 置 false、清文字提示，未胡牌时清除手牌置灰。锚点：layer/BoxHzmjMainView.ts → onShowTrustee。
30. onShowTrustee 的派发前提是房间规则开启托管（BoxRoomData.getBoxRoomTrustee() 即规则 bot > 0）；规则关闭托管的房间即使自己已托管也不收起操作区。锚点：controller/cmd/gameCmd/GamePowerCmd.ts → _checkShowTrustee；common_game/data/BoxRoomData.ts → getBoxRoomTrustee。
31. onShowTrustee 共五个派发点：自己收到空权限（power == POWER_ID_NONE，值为 0）、自己碰、自己杠、自己胡牌展示（HuEx）、自己胡牌展示（ResultHu）。锚点：controller/cmd/gameCmd/GamePowerCmd.ts → _checkShowTrustee；GamePungCmd.ts → execute；GameKongCmd.ts → execute；GameHuExCmd.ts → _dispatchSetHu；GameResultHuCmd.ts → _dispatchSetHu。
32. 他人进入手动托管时全员收到一条提示条："{昵称}进入托管状态"（MessageSimpleBoxView），自己进入托管不弹这条提示条而是弹遮罩。锚点：common_game/controller/cmd/NotifyPlayerActionCmd.ts → _playerBot。
33. 自动摸打（kBotAuto）给他人只做数据刷新，不弹"进入托管状态"提示条；取消自动摸打同样只有数据刷新与时钟恢复。锚点：common_game/controller/cmd/NotifyPlayerActionCmd.ts → _playerBotAuto / _playerUnBotAuto。
34. 头像托管角标只表达"手动托管"：更新玩家信息时写 showTrust(player.isBot && !player.isBotAuto)，自动摸打不显示角标；实现为 KW_PLAYER.C_Trustee.selectedIndex = 1/0。锚点：layer/BoxHzmjPlayerView.ts → updatePlayerInfo；layer/BoxHzmjPlayerMatchView.ts → updatePlayerInfo（注释"自动摸打不显示托管角标"）；common_game/layer/component/BasicPlayerComp.ts → showTrust。
35. 金币场与好友房的头像层不同源：Game42319.initUI 按 isBoxRoom 决定加载 BoxHzmjPlayerView（好友房）还是 BoxHzmjPlayerMatchView（金币场/匹配场），因此金币场的托管角标由 BoxHzmjPlayerMatchView 维护。锚点：Game42319.ts → initUI；layer/BoxHzmjPlayerMatchView.ts → updatePlayerInfo。
36. 状态事件只切 kBot/kUnBot 的角标：BasicPlayerComp.onPlayerStateChange 的 switch 只列 kBot 与 kUnBot（kBotAuto/kUnBotAuto 不在其中），与第 34 条的"自动摸打不显示角标"口径一致；但 initState/onPlayerForceRefresh 用的是 showTrust(player.isBot)，未排除 isBotAuto，同一切换器存在两套判定。锚点：common_game/layer/component/BasicPlayerComp.ts → onPlayerStateChange / initState / onPlayerForceRefresh。
37. 离开与重置时清角标：玩家离开、清空其他玩家、清空全部头像、重置 UI 都会 showTrust(false)（并 showOffline(false)），避免残留到下一局。锚点：layer/BoxHzmjPlayerMatchView.ts → onPlayerLeave / _clearOtherPlayers / _clearAllPlayerHeads / resetUI；common_game/layer/component/BasicPlayerComp.ts → resetFupanUI。

## 三、超时倒计时显示（桌面）

38. 桌面倒计时节点是 KW_DeskCent.KW_Clock_Num：每次 setClock 先清空文本再重建；time > 0 进入秒级 CountdownTime，剩余秒数小于 10 时补 0 显示两位；time == 0 时固定显示"00"。锚点：layer/BoxHzmjMah2DView.ts → setClock。
39. setClock 的两条显示守卫：复盘模式直接 return（不显示倒计时）；time > 999 视为无效值直接 return（不刷新文本、不重启计时）。锚点：layer/BoxHzmjMah2DView.ts → setClock。
40. 倒计时样式与音效：剩余 <= 3 秒切强调字体（Fntdaojishi02-export），否则用普通字体；仅当座位是自己、playSound 为 true 且 GameData.getAutoHu() 为 false 时，才在 <= 3 秒播倒计时音效 countdown2。锚点：layer/BoxHzmjMah2DView.ts → setClock；data/GameData.ts → getAutoHu。
41. 同回合长考引导：倒计时过程中"(首次值 - 当前剩余) > 8 秒"且尚未弹过引导时，对操作者弹出道具使用引导（GameBoxPropGuideView，参数 localSeat）；自己座位与未开局房间不弹；每次 setClock 都会先隐藏该引导并重置 _isTipOperation。锚点：layer/BoxHzmjMah2DView.ts → setClock / tipPlayerOperation。
42. 座位亮光与倒计时联动：setDeskCentLight 只点亮当前座位光圈并按秒做透明度闪烁；time == 0 时隐藏该光圈；复盘模式或 time > 999 只停止闪烁计时并直接返回，不改变当前亮光可见性。锚点：layer/BoxHzmjMah2DView.ts → setDeskCentLight。
43. 倒计时的清理时机：流局处理显式发 setClock(自己, 0) 与 onShowDeskCentLight(自己, 0) 把文本重置为"00"并熄灯；小局结束 onGameEnd 调 setClockHide 清文本停表；主界面重置同时清文本与停表。GameEventBoxHzmj.setClockHide 在 42319 内没有派发方（死事件，无派发方），只保留监听与直接调用。锚点：controller/cmd/gameCmd/GameDrawnCmd.ts → execute；layer/BoxHzmjMah2DView.ts → onGameEnd / resetUI / setClockHide；config/FguiViewDefine.ts → setClockHide。

## 四、操作超时弹层与超时回归

44. 操作超时弹层两行文本固定：主文案"玩家{昵称}操作超时，超时{N}秒自动解散房间"，次行"当前超时时间{M}秒"；M 以传入的已超时秒数为起点，由界面自己每秒 +1 刷新。锚点：common_game/layer/boxRoom/BoxRoomTimeoutTipView.ts → initDesc / initTimer。
45. 弹层参数来源：玩家昵称、好友房最大超时解散秒数、当前已超时秒数；已超时秒数小于配置的最小提示秒数时以配置值作为起点；弹出后把房间累计超时时间（playerPassTime）清零。锚点：common_game/controller/cmd/NotifyPlayerActionCmd.ts → _playerBotHintTimeout。
46. 弹层前置守卫四条：增量更新（justUpdateData）不弹；按座位查不到玩家不弹；超时者是自己 numid 不弹；复盘模式不弹弹层，改为向该座位派发托管超时气泡事件。锚点：common_game/controller/cmd/NotifyPlayerActionCmd.ts → _playerBotHintTimeout；common_game/layer/component/BasicPlayerComp.ts → onNotifyBotHintTimeout。
47. 弹层两个按钮：关闭按钮只隐藏界面（方法内未停止每秒自增计时）；提醒按钮调起微信"提醒他"分享，用于催队友回桌。锚点：common_game/layer/boxRoom/BoxRoomTimeoutTipView.ts → onBtnClose / onBtnTip。
48. 弹层不携带座位标识：参数只有昵称与两个时间值，关闭与回归都作用于同一视图实例；多人同时超时时界面只显示最近一次打开的参数，无法为每人保留独立弹层。锚点：common_game/layer/boxRoom/BoxRoomTimeoutTipView.ts → IBoxRoomTimeoutTipViewParam / initUI。
49. 超时回归：任意带 seat 的下行协议处理完后，若该座位仍处于"超时提示中"且未断线，则关闭超时弹层、弹一条"玩家{昵称}已返回"（显示 3 秒）、向该座位派发 onNotifyPlayerBackGame、把超时提示标记复位。锚点：controller/gameController.ts → svrPushToClient / _playerBotHintTimeoutEnd。
50. 回归检查的跳过条件：消息体没有 seat 或 seat 非数字直接返回；按座位查不到玩家直接返回；玩家 isWireBreak 为 true 也返回——此时弹层不关闭、"已返回"提示不出现、超时标记保留，等待下一次下行。锚点：controller/gameController.ts → _decodeSeatForBotHint / _playerBotHintTimeoutEnd。
51. 回归检查不区分是否增量数据：svrPushToClient 在 execute 之后无条件调用 _playerBotHintTimeoutEnd，复盘批量喂包（dealMultipleFupanData / dealBatchFupanData）也会走到该逻辑。锚点：controller/gameController.ts → svrPushToClient / dealMultipleFupanData / dealBatchFupanData。
52. 自己座位的特殊处理：超时检查之前先判断该座位是否为自己，是则无条件派发 onShowFanView（公共番型面板 visible 置 true）；而自己收到权限协议时又会派发 onHideFanView。因此番型面板显隐与"是否真的超时"无关，随自己的每次回包与权限包交替切换。锚点：controller/gameController.ts → _playerBotHintTimeoutEnd；controller/cmd/gameCmd/GamePowerCmd.ts → _updateSeatPowerView；common_game/layer/boxRoom/BoxRoomFanView.ts → onShowFanView / onHideFanView。
53. 超时弹层的清理还有第二条路径：小局结束/强制解散时统一 hideFguiAllType(ViewLayer.Pop) 并显式 hide GamePopTrustView，弹层随之关闭（不仅依赖回归检查）。锚点：common_game/controller/cmd/NotifyBoxActionCmd.ts → _dealEndGame；common_game/controller/cmd/NotifyMatchActionCmd.ts → _dealEndGame。

## 五、托管、超时与离线惩罚提醒气泡

54. 玩家头像旁的提示气泡只有一个容器（KW_BOT_TIP，自己的 PlayerSelfBase、他人的 PlayerLeft/Right/TopBase 均为同构组件，内部单行文本 KW_TXT_TIP），托管次数提醒、超时提醒、离线解散警告三类文案共用它，后到者覆盖先到者。锚点：fgui_uideclare/box_hzmj_player/FGUI_box_hzmj_player_PlayerSelfBase.d.ts → KW_BOT_TIP；FGUI_box_hzmj_player_BotTipLeft.d.ts → KW_TXT_TIP；common_game/layer/component/BasicPlayerComp.ts → onNotifyBotCount / onNotifyBotHintTimeout / onNotifyOfflineDismissWarn。
55. 托管次数气泡文案："{昵称}已托管出牌{N}次，\n若结算时为托管状态，本局将解散，点击提醒他"；显示 3 秒后自动隐藏。触发阈值来自好友房最大托管出牌次数配置，达到或超过阈值才会派发。锚点：common_game/layer/component/BasicPlayerComp.ts → onNotifyBotCount；common_game/data/TableData.ts → addBotCount。
56. 托管次数的累计入口在出牌协议：每次收到自己或他人出牌，GamePlayCmd 调 TableData.addBotCount(localSeat, justUpdateData)；仅当房间规则 bot > 0 且该玩家 isBot 时才累加，增量阶段（justUpdateData）累加后直接返回不弹气泡。锚点：controller/cmd/gameCmd/GamePlayCmd.ts → _updatePlayData；common_game/data/TableData.ts → addBotCount。
57. 托管次数气泡不对自己显示（自己座位且非复盘直接 return），复盘模式下自己座位也显示。锚点：common_game/layer/component/BasicPlayerComp.ts → onNotifyBotCount。
58. 超时解散气泡文案："操作操时的时间过长，触发超时解散~"（原文如此，含错别字"操时"），显示 3 秒后隐藏；该气泡只在复盘分支被派发，正常对局用第 44 条的弹层表达。锚点：common_game/layer/component/BasicPlayerComp.ts → onNotifyBotHintTimeout；common_game/controller/cmd/NotifyPlayerActionCmd.ts → _playerBotHintTimeout。

## 六、托管与超时的自动举报兜底

63. 开局协议写入两个举报时间点：bot_time（有毫秒字段 bot_time_ms 时取毫秒 ÷ 1000，否则用秒字段 bot_time）作为托管举报时间；auto_bot_time 只处理毫秒字段 auto_bot_time_ms，没有秒字段兜底，写入出牌预举报时间。锚点：controller/cmd/gameCmd/GameStartGameCmd.ts → execute；common_game/controller/reportController.ts → setBotTime / setPreReportTime。
64. 举报计时器每 0.1 秒步进；累计时间走过托管举报时间点时，对场上所有 isBot 或 isBotAuto 的玩家各上报一次，同一倒计时周期只查一次。锚点：common_game/controller/reportController.ts → _tick / _checkBotUser / _botChecked。
65. 累计时间走过预举报时间点时上报预举报名单；名单由每次收到权限协议时把 isBotAuto 玩家的座位追加进列表累积（不去重），直到时钟重置才清空，因此同一玩家可能被重复追加。锚点：common_game/controller/reportController.ts → _checkGamePreReport / setPreReportList / _resetClock；controller/cmd/gameCmd/GamePowerCmd.ts → _checkBotAutoReport。
66. 倒计时自然结束（累计时间超过显示时长）时对所有人上报一次，报文 who 的 num_id 与 area_id 都为 0；报文按房型区分：包厢用 UserTimerOutRequest（带 boxid），匹配场用 TimeoutRequest（带 table_id）。指定座位举报时要求该玩家 areaid > 0 且 numid > 0，否则跳过不报。锚点：common_game/controller/reportController.ts → _tick / _checkEnd / _report。
67. 新的服务器时钟（time > 0）会重置举报检查标记与预举报名单并重启计时器，因此同一周期内"托管举报""出牌预举报"各只触发一次；setClock(0) 不停表也不重置（停表由小局结束负责）；重连时钟额外写入已走时间，使显示与举报进度从中间开始。锚点：common_game/controller/reportController.ts → setClock / setRelinkClock / _resetClock。
68. 取消托管时用 setUnBotClock 恢复"原始时钟"：只覆盖剩余显示值（优先 display_ms ÷ 1000，其次 display），不重置已走时间、不重建计时器；已进入托管后（onPlayerBot 且本周期已检查过）会立刻再查一次托管玩家，补报新增托管者。锚点：common_game/controller/reportController.ts → setUnBotClock / onPlayerBot / _checkBotUser。
69. 小局结束统一收口：停表（onGameEnd 重置时钟并 unschedule）；清空所有玩家的托管与自动摸打标记；派发取消状态事件；隐藏全部 Pop 层与托管遮罩。包厢派发 kUnBot 与 kUnBotAuto 两条，匹配场只派发 kUnBot。锚点：common_game/controller/reportController.ts → onGameEnd；common_game/controller/cmd/NotifyBoxActionCmd.ts → _dealEndGame；common_game/controller/cmd/NotifyMatchActionCmd.ts → _dealEndGame。

## 七、DelayCall 与延迟兜底

70. DelayCall 语义是"同一目标只保留最后一次"：先 fgui.GTween.kill(目标)，再创建延迟回调；对同一对象连续调用会取消上一次尚未到期的延迟。锚点：config/FguiViewDefine.ts → DelayCall。
71. 限时文字提示默认 1.3 秒后自动隐藏，用于"当前未过手，无法碰牌""当前未过手，无法吃胡"这类拒绝反馈；连续触发时以最后一次为起点重新计时。锚点：layer/BoxHzmjTipAniView.ts → onShowTextTimeTips；controller/cmd/gameCmd/GameNotifyInfoCmd.ts → execute（两处均传 1.3）。
72. 常驻文字提示会主动取消正在进行的自动隐藏：显示前若正处于限时计时中，先把计时标记置 false 并 kill 文本节点上的 tween，之后该提示不再自动消失。清除提示有守卫：处于限时提示且未强制清除时忽略本次清除，只有强制清除（bClear = true）才真正隐藏并 kill。锚点：layer/BoxHzmjTipAniView.ts → onShowTextTips / onClearTextTips；controller/cmd/gameCmd/GamePowerCmd.ts → _updateFirstPlayTips（dispatch onClearTextTips, true）。
73. 摊牌后结束等待有 1 秒兜底：playHuEnd 派发 onSendEndWaitDelay，主界面 scheduleOnce(1 秒) 后调用 sendEndWait，避免胡牌动画流程中断时对局不推进。锚点：layer/BoxHzmjMah2DView.ts → playHuEnd；layer/BoxHzmjMainView.ts → sendEndWaitDelay。
74. 胡牌流程内另有"只发一次"守卫：_playHuAnimations 用 _endWaitSent 标记保证多家胡/多回调场景下 sendEndWait 只上行一次；首局发牌结束（GameEndWaitCmd 读到 takeFirstEndWait）与三个重连场景命令也各自补发一次。锚点：controller/cmd/gameCmd/GameHuExCmd.ts → _playHuAnimations；controller/cmd/gameCmd/GameEndWaitCmd.ts → execute；controller/cmd/sceneCmd/SceneActionCmd.ts / SceneTakeFirstCmd.ts / SceneMixCardCmd.ts。
75. 总结算延迟 2 秒弹出（已在显示则跳过，延迟回调内数据为空不弹），用于避开胡牌/小结算动画抢层。锚点：layer/BoxHzmjMainView.ts → showBoxTotalResultView。
76. 骰子兜底隐藏：非跳过动画时，等骰子 Spine 播完再延迟 1 秒隐藏两颗骰子；跳过动画（skipAni）只播一次 animation1，不设置该延迟，只能由后续显式隐藏事件收起。锚点：layer/BoxHzmjMah2DView.ts → showDice / hideDice。
77. 结算分数节点延迟 2 秒清理：onClearResultScore 先为每个未完成的座位执行保底回调（防止依赖动画回调卡死），再对每个节点 scheduleOnce(2 秒) 隐藏并停动画；同时自增 runId 使本轮旧回调失效，避免清理后重复触发。锚点：layer/BoxHzmjTipAniView.ts → onClearResultScore。
78. 重置与离开会取消全部延迟回调：主界面重置与控制器的 clear 都调用 unscheduleAllCallbacks，防止上一局的延迟发结束等待、延迟弹结算在下一局触发；被取消的延迟不会补发，需要后续事件重新触发。锚点：layer/BoxHzmjMainView.ts → resetUI；controller/gameController.ts → clear。
