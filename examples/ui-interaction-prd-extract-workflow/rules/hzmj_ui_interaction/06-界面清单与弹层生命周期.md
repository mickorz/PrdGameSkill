# 界面清单与弹层生命周期（客户端 UI 交互基准）

> 来源：input-ui/xuanwulobby/assets/42319 代码逆向，提取日期 2026-11-11。锚点格式：文件 → 方法。检查需求文档对界面清单与弹层生命周期相关交互的描述是否完整、与实现一致。

锚点路径约定：以 `42319/` 开头的锚点相对 `input-ui/xuanwulobby/assets/42319/`；以 `common_game/`、`node_modules/` 开头的锚点相对 `input-ui/xuanwulobby/assets/`。

范围说明：本文件只收录「界面清单（@FguiView）/ 弹层开合 / 防抖与延迟 / 换房清理」范围内的可验证事实。按钮权限与操作区见 01，听牌数据与听牌按钮语义见 02，结算动画与飘分细节见 03，断线重连命令链见 04，托管见 05，倒计时与常驻元素见 07，开局动画见 08。FGUI 工程目录 `input-ui/kawuxing-fgui` 的 `boxkawuxing_mah_*` 分包仅作同名同构组件结构对照，42319 运行时引用的是自身 `assets/42319/fgui/box_hzmj_*` 分包。

## 一、模块启动与界面清单

1. 杭州麻将模块入口固定按「控制器初始化 → 数据初始化 → 清动态层登记 → 首屏 UI 加载」四步执行：`GameController.instance.init()`、绑定 `GameInstController.GameController`、`GameData.init()`、`this.init()`（`DynamicController.inst.clearViews()`）、`this.initUI()`。每次进入模块都会完整重走这条链。锚点：42319/Game42319.ts → HzmjView.start() / init()

2. 首屏同步加载的界面固定为四个：BoxHzmjBackView（背景）、BoxHzmjMah2DView（2D 牌桌）、BoxHzmjMainView（主界面）、BoxHzmjTipAniView（提示动画）；由 `pfbm.loadGameResourceProcess` 的 `strViewList` 一次性拉起。锚点：42319/Game42319.ts → HzmjView.initUI()

3. 玩家信息层按房型二选一、互斥加载：`BoxRoomData.inst.isBoxRoom()` 为真时加载 BoxHzmjPlayerView，否则加载 BoxHzmjPlayerMatchView；两者不会同时出现在同一局。锚点：42319/Game42319.ts → HzmjView.initUI()；42319/layer/BoxHzmjPlayerView.ts → @FguiView；42319/layer/BoxHzmjPlayerMatchView.ts → @FguiView

4. 复盘模式（`isFupanMode()`）在好友房链路上额外加载 BoxRoomFupanView，并且不加载 GameBaseBoxMenuView 与 GameBaseBackButtonsView；即复盘态没有常规菜单层与返回按钮层。锚点：42319/Game42319.ts → HzmjView.initUI()

5. 非复盘好友房加载 GameBaseBoxMenuView + GameBaseBackButtonsView；匹配场（`isMatchRoom()`）在玩家层之外再追加 GameMatchButtonsView 按钮层。锚点：42319/Game42319.ts → HzmjView.initUI()

6. 延后加载清单固定包含：GameBackPhoneInfoView、BoxHzmjCardDownView、GameCharmPropView、GameHeadLuckyView；随后按房型追加 GameBackButtonsView（好友房）或 GameBackButtonsMatchView（匹配场），非复盘再追加 GameMenuView。锚点：42319/Game42319.ts → HzmjView.initUI()

7. 首屏全部界面加载完成后才播放背景音乐，并在复盘模式执行 `FupanNewController.prepareWithGame([GP_PLAY_LMTS, GP_END_GAME])` 与 `start()`；即复盘进度链以出牌流水与结束游戏两条协议作为收束点。锚点：42319/Game42319.ts → HzmjView.initUI()（loadFinishAll）

8. 延后界面加载完成后的固定动作有三项：预加载听牌与小结算资源（`preloadGameRes`）；非复盘时用 `pfbm.uiFgui(GamePlayerMysticView).showFgui().close()` 预实例化玄学界面后立即关闭；向 BoxHzmjMainView 派发 `loadFinishAll`。锚点：42319/Game42319.ts → HzmjView.initUI()（loadFinishAllDelay）；FguiEmit(BoxHzmjMainView, "loadFinishAll")

9. 主界面与 2D 牌桌层互相注入手牌组件且不保证顺序：MainView.initUI 尝试从已创建控制器里取 BoxHzmjMah2DView 的 `selfHand`，取不到时保持未赋值；Mah2DView.initUI 反向获取 BoxHzmjMainView 并调用 `initSelfHand(this.selfHand)` 完成注入。因此 MainView 在 Mah2D 尚未创建完成的窗口内没有可用的手牌控制器。锚点：42319/layer/BoxHzmjMainView.ts → initUI()；42319/layer/BoxHzmjMah2DView.ts → initUI()

10. BoxHzmjMainView 的 `@FguiOn loadFinishAll` 只在匹配场执行：向 GameMenuView 派发 `onUpdateMahLeftComp`，注入 `ui://box_hzmj_main/BoxHzmjMahLeftComp` 与组件名。好友房不执行该校准。锚点：42319/layer/BoxHzmjMainView.ts → loadFinishAll()

## 二、界面分层、排序与资源绑定

11. 全部游戏界面使用 `gf.ViewLayer.Base`，仅有三个例外：BoxHzmjSpecfView（做牌）与 BoxHzmjTingPaiView（听牌）使用 `gf.ViewLayer.Pop`，BoxHzmjTestView（测试）使用 `gf.ViewLayer.Top`。锚点：各界面类 @FguiView 的 `layer` 字段（42319/layer/*.ts）

12. 各游戏界面在 Base 层内使用不同的 `sortingOrder` 分组：BackView=Back、CardDownView=Card_Down、PlayerView/PlayerMatchView=Player、Mah2DView=Card、MainView=Main、TipAniView=Ani；其中 CardDownView 的类注释明确其定位为「麻将牌桌和背景动画中间层」。锚点：42319/layer/BoxHzmjBackView.ts / BoxHzmjCardDownView.ts / BoxHzmjPlayerView.ts / BoxHzmjPlayerMatchView.ts / BoxHzmjMah2DView.ts / BoxHzmjMainView.ts / BoxHzmjTipAniView.ts → @FguiView 的 `sortingOrder`

13. 安全区适配只对 UI 层开启：Back、CardDown、Player、PlayerMatch、Main、TipAni、Specf、Test 均 `safeArea: true`；2D 牌桌 BoxHzmjMah2DView 明确 `safeArea: false`，牌桌不做安全区裁剪。锚点：各界面类 @FguiView 的 `safeArea` 字段

14. BoxHzmjMah2DView 的资源绑定与 42319 自有分包不同：`bundle: "fgui_lobby"`、`packages: ["game_mah"]`、`fguiObject: "BoxScmjMah2DView"`，即 2D 牌桌复用大厅包内的通用麻将桌组件。锚点：42319/layer/BoxHzmjMah2DView.ts → @FguiView

15. 剩余牌组件 BoxHzmjMahLeftComp 使用 `FuiCommonViewDefine.FguiPackageGame` 作为 bundle，通过 `name` 与 `fguiObject` 都为 `BoxHzmjMahLeftComp` 绑定，仅声明 `packages: [box_hzmj_main]`；主界面先直接调用一次绑定，之后由通用事件 `onNotifyGameBindMahLeftCompToBackButtonsView` 再次触发绑定。锚点：42319/layer/comp/BoxHzmjMahLeftComp.ts → @FguiView；42319/layer/BoxHzmjMainView.ts → bindMahLeftCompToBackButtonsView()

16. 听牌弹层是唯一声明 `cachable: true` 与 `notLoading: true` 的游戏界面：框架的 `enableCahche` 默认为 true，因此关闭时组件进入 FGUI 缓存不销毁，二次打开复用同一组件实例；`notLoading` 使其加载时不弹通用等待框。锚点：42319/layer/BoxHzmjTingPaiView.ts → @FguiView；node_modules/core/src/lib/gameframe.ts → ViewPluginImpl.enableCahche / 关闭分支（`!cachable || !enableCahche`）

17. 提示动画层整层不接收触摸：TipAniView.initUI 把 `view.touchable` 置为 false，覆盖在牌桌上的动画不会拦截点击。锚点：42319/layer/BoxHzmjTipAniView.ts → initUI()

## 三、常规弹层开合

18. 测试界面位于 Top 层，由主界面的键盘监听切换：T 键在「未打开」时 `showFgui()`、已打开时 `hideFgui()`；发布配置 `GameConfig.value == 2` 且非 Web 平台时 T 键直接不响应；键盘回调在 MainView.onDestroy 中解绑。锚点：42319/layer/BoxHzmjMainView.ts → _onKeyDown() / onDestroy()；42319/layer/BoxHzmjTestView.ts → @FguiView

19. 记牌器为「长按桌面」弹层：仅当自己玩家 `cardCounting == true`、手牌区处于触摸态且当前未触摸某张牌时开始累计时间；累计超过 0.3 秒才 `showFgui({ touchShow: true })` 并置 `_isHoldingJpq`，同一次长按不重复打开；松手时若已打开则 `hideFgui()` 并把计时归零。锚点：42319/layer/BoxHzmjMainView.ts → touchTick / _isHoldingJpq / _touchTime

20. 记牌器另有独立入口：收到通用事件 `onClickCardCount` 时直接 `showFgui()` 打开。但 `BoxHzmjJpqView` 在模块内没有任何 @FguiView 实现，调用不会被渲染（详见 06#77）。锚点：42319/layer/BoxHzmjMainView.ts → onClickCardCount()

21. 听牌弹层是开/关切换，而不是按 visible 判断：`pfbm.isShowFgui(BoxHzmjTingPaiView)` 为真时执行 `hideFgui()` 并结束；否则用当前 `GameData.getTingVaule()` 数据 `showFgui(tingValue)`。`isShowFgui` 判定的是当前是否存在活跃视图实例（关闭后被移除，缓存组件不算活跃）。锚点：42319/layer/BoxHzmjMainView.ts → onBtnTing()；node_modules/kiwi/src/core/PrefabManger.ts → isShowFgui；node_modules/core/src/lib/gameframe.ts → haveView/closeView

22. 抬手提牌且该牌存在「打这张能听」的数据时，直接以该份听牌数据打开听牌弹层，不需要先点听牌按钮。锚点：42319/layer/BoxHzmjMainView.ts → onUpDownMah()（`showFgui(tingInfo[mahValue])`）

23. 点击牌桌空白（手牌组件回调 `onTouchOther`）会关闭听牌弹层，并同时派发通用 `onTouchTable`。锚点：42319/layer/BoxHzmjMainView.ts → onTouchOther()

24. 自己抓牌（`checkShowTingBtnOnTake`）与权限刷新（`checkShowTingBtnOnPower`）都会关闭听牌弹层：前者同时隐藏听牌按钮；后者在「有出牌权」时隐藏按钮、在「有胡权」时关闭弹层（两个条件独立执行）。这两条命令由可达的 GP_TAKE / GP_POWER 驱动。锚点：42319/layer/BoxHzmjMainView.ts → checkShowTingBtnOnTake() / checkShowTingBtnOnPower()；42319/controller/cmd/gameCmd/GameTakeCmd.ts / GamePowerCmd.ts → execute

## 四、结算类弹层

32. 小结算弹层 BoxRoomGzmjResultView 在模块内唯一的打开点是 ResultCmd.execute（`showFgui(resultViewData)`）；GameEndCmd 不弹结算。正常对局下 ResultCmd 无触发源（ResultHu 链不可达，复盘改由 gameResult 直接执行 CMD_GAME_RESULT），可达性详见 03#74。锚点：42319/controller/cmd/helperCmd/ResultCmd.ts → execute；42319/controller/cmd/gameCmd/GameEndCmd.ts → execute

33. 开新局/再来一局的重置会强制关闭小结算弹层：MainView.resetUI 末尾 `hideFgui(BoxRoomGzmjResultView)`。锚点：42319/layer/BoxHzmjMainView.ts → resetUI()

34. 大结算弹层打开有「延迟 + 防重」：收到 `showBoxTotalResult` 事件先判断 BoxRoomTotalResultView 已显示则直接返回；否则 `scheduleOnce` 延迟 2 秒读取 BoxRoomData 的大结算数据，数据非空才 `showFgui<BoxRoomTotalResult>(totalResultData)`。该事件的唯一派发点随 ResultHu 链不可达（详见 03#75）。锚点：42319/layer/BoxHzmjMainView.ts → showBoxTotalResultView()

35. 大结算数据先由 gameTotalResult 执行 CMD_GAME_TOTAL_RESULT 组装进 BoxRoomData，再计算 `directShow = isFupanMode() || (dismisser?.area_id !== 0 && dismisser?.num_id !== 0)`；该写法下 dismisser 缺省（undefined）也会满足 `!== 0`，因此非复盘且未下发解散者时同样直弹；仅当 `hasBotDismiss`（任一 user_results.is_bot_dismiss）为真时不直弹。锚点：42319/controller/gameController.ts → gameTotalResult()；42319/controller/cmd/helperCmd/TotalResultCmd.ts → execute

36. 复盘模式阻断了胡牌命令内的结算弹层：GameResultHuCmd 的 `_showResultView` 在复盘下只 `reportFinish(GP_Hzmj_RESULT_HU)` 并返回，`_showTotalResultView` 直接返回；复盘的小结算改由 GameController.gameResult 用缓存数据执行 CMD_GAME_RESULT 弹出。锚点：42319/controller/cmd/gameCmd/GameResultHuCmd.ts → _showResultView() / _showTotalResultView()；42319/controller/gameController.ts → gameResult()

37. 小结算界面出现时派发通用 `onShowGameResult`，主界面据此隐藏预约洗牌按钮 `KW_BTN_Xi_Pai`。锚点：42319/layer/BoxHzmjMainView.ts → onShowGameResult()

38. 预约洗牌弹层由主界面洗牌按钮打开：`showFgui(BoxRoomXiPaiView).autoTopFgui()` 置顶显示，同时把按钮上的红点 tip 页签复位为 0 并上报埋点。锚点：42319/layer/BoxHzmjMainView.ts → onBtnXiPai()

39. 洗牌按钮本身有五重显示守卫：自己没有胡牌、匹配场、已到最后一局、已预约洗牌、复盘模式均不显示（复盘分支只强制隐藏）；每日首次显示时才把 C_ShowTip 切到 1 页。锚点：42319/layer/BoxHzmjMainView.ts → onUpdateReserveShuffle()

40. 两类轻量提示走通用弹层：收到 NIF_LIMIT_PENG/NIF_LIMIT_HU 时用 `onShowTextTimeTips` 显示 1.3 秒文案；收到 NIF_NO_PASSPORT 时弹 `MessageSimpleBoxView` 文案「手里没豆时，平胡不能被点炮」，展示 1.5 秒。锚点：42319/controller/cmd/gameCmd/GameNotifyInfoCmd.ts → execute

## 五、防抖、延迟与失败兜底

43. 结果分数展示带代际号（runId）防串台：每次 `onShowResultScore` 先执行 `onClearResultScore` 再自增 `_showResultScoreRunId`；座位完成回调与整轮完成回调都校验 runId，不匹配直接丢弃。锚点：42319/layer/BoxHzmjTipAniView.ts → onShowResultScore() / _finishOneResultScoreSeat() / _finishResultScore()

44. 结果分数整轮完成只允许一次：`finished` 标记命中后重复调用只打日志返回；展示总数为 0 时立即走完成逻辑；完成后统一 `reportFinish(GP_HU_EX)`，`endWaitFlag` 为真才补发 `sendEndWait()`（该分支因桌分固定 endWait=false 实际不可达，见 03#84）。锚点：42319/layer/BoxHzmjTipAniView.ts → _tryFinishEmptyResultScore() / _finishResultScore()

45. `onClearResultScore` 是飘分阶段的失败恢复兜底：先按座位强制触发尚未完成的完成回调，清空回调表，再自增 runId 使旧回调全部失效，并对每个分数节点 `scheduleOnce(..., 2)` 延迟 2 秒隐藏并停止动画，避免客户端结束过快时节点被误隐藏。锚点：42319/layer/BoxHzmjTipAniView.ts → onClearResultScore()

46. 收到结束游戏（onGameEnd）时 TipAniView 立即执行上述兜底清理，不等待分数动画自然结束。锚点：42319/layer/BoxHzmjTipAniView.ts → onGameEnd()

47. 定时文字提示有自动消失与替换语义：`onShowTextTimeTips` 显示后 `DelayCall(time 默认 1.3 秒)` 自动隐藏；`onShowTextTips`（常驻提示）在 `_btnTips` 为真（当前正有限时提示）时先复位标记并 kill 文本 Tween，避免旧延时把新提示关掉。锚点：42319/layer/BoxHzmjTipAniView.ts → onShowTextTimeTips() / onShowTextTips()

48. 清理文字提示有「保护期」：当 `_btnTips` 为真（正在倒计时的限时提示）且未传强制参数时，`onClearTextTips` 直接返回不清理；只有 `bClear=true` 才能强制清掉（首出庄提示用它清场）。锚点：42319/layer/BoxHzmjTipAniView.ts → onClearTextTips()；42319/controller/cmd/gameCmd/GamePowerCmd.ts → _updateFirstPlayTips()

49. 台面胡牌标识带动画推进时，`onShowResultTableSign` 在写入 `C_HuType` 后用 `scheduleOnce` 延迟 1.5 秒回调 `nextCallBack(aniIndex)` 推进下一段；不带回调时只显示不推进。锚点：42319/layer/BoxHzmjMainView.ts → onShowResultTableSign()

50. 结束等待支持延迟上行：`sendEndWaitDelay(num=1)` 通过 `scheduleOnce` 默认 1 秒后调用 `GameController.sendEndWait()`。锚点：42319/layer/BoxHzmjMainView.ts → sendEndWaitDelay()

51. 匹配等待面板的计时是无限循环的 30 秒：`showMatch(true)` 把 `_matchTime` 复位 30 并每秒 tick，减到负数后回到 30 继续；标题固定两位补零加「秒」。锚点：42319/layer/BoxHzmjTipAniView.ts → showMatch() / matchTimeSche

52. 匹配等待面板的玩法提示每 8 秒横向轮播一次，共 8 条文案（财神、爆头、财飘、三摊承包、连庄倍数、十风牌、缺一色等），轮播依赖节点上的 `GTween.delayedCall(8)`。锚点：42319/layer/BoxHzmjTipAniView.ts → updateMatchTips()

## 七、重连与复盘对弹层的影响

61. 断线重连的 `gameSceneBack` 中，「先派发 onResetUI 再执行场景命令」的分支实际不可达：它位于 `HzmjDataParser.parseGameMsg(state, sceneData)` 解析成功分支内，而解码表只登记消息 id、GAME_STATUS 状态键整段被注释，解析恒为 null。因此重连不会通过 onResetUI 关闭已有弹层或重置桌面。锚点：42319/controller/gameController.ts → gameSceneBack()；42319/protocol/GameGlcProtocol.ts → GAME_MSG_DECODERS

62. 重连后仍会无条件刷新三项界面状态：`onIsGameStart(state > 0)`、`onIsGameStartPlayerPos(state > 0 || 当前局数 != 0)`、`onShowSelfPlayer(true)`（显示自己头像）；这三项与解析结果无关。锚点：42319/controller/gameController.ts → gameSceneBack()

63. 复盘/回放的界面重置是显式的：dealBatchFupanData 先派发 `onResetUI`，再以 justUpdateData 逐条静默写数据，最后执行 CMD_FUPAN_RECOVER_GAME_SCENE；RecoverGameSceneCmd 在 `justUpdateData === true` 时直接返回，否则按 currentXyid 分两支恢复（GP_START_GAME 只恢复墙/骰/手牌/庄，其它走墙/庄/骰/手牌/河/权限/胡牌全量）。锚点：42319/controller/gameController.ts → dealMultipleFupanData() / dealBatchFupanData()；42319/controller/cmd/RecoverGameSceneCmd.ts → execute()

64. 复盘权限按钮按座位逐个重放：`_recoverPowerBtns` 遍历人数取 `GameData.getFuPanPower(i)` 并派发 `setFupanPower(i, power)`；主界面据此显示按座位编号的碰/杠/胡/过按钮组（KW_BTN_Peng_{i} 等），不受主操作面板页控制。锚点：42319/controller/cmd/RecoverGameSceneCmd.ts → _recoverPowerBtns()；42319/layer/BoxHzmjMainView.ts → setFupanPower()

65. 复盘模式抑制两类局内提示：玩家层 `onShowActionSign` 与匹配玩家层同构实现直接 return，不显示准备/坐下标识；TipAniView 在 `onMsgShowZhuangTips(show=true)` 且复盘时直接 return，不显示庄/闲提示条。锚点：42319/layer/BoxHzmjPlayerView.ts / BoxHzmjPlayerMatchView.ts → onShowActionSign()；42319/layer/BoxHzmjTipAniView.ts → onMsgShowZhuangTips()

66. 复盘 replay 的胡牌恢复不播动画也不弹层：GameResultHuCmd 在 `_isReplay` 分支只隐藏出牌放大、修正抢杠组合、摊牌、显示台面标识后返回，不进入胡牌动画链与结算弹层。锚点：42319/controller/cmd/gameCmd/GameResultHuCmd.ts → _updateHuView()
