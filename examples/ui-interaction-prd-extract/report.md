## 3. 重点问题详情

### Q01【P0 / MISSING】断线重连与场景恢复机制整体缺失

- **问题性质**：基准用整个文件（04-断线重连与场景恢复，21 条）描述的成体系机制，需求文档完全未覆盖。
- **原文**：位置"三、对局流程 → 局中信息 → 玩家头像信息 → 玩家状态"。引文："离线状态：头像处覆盖断线图标，且显示断线计时，格式为分秒'00:00'，每次断线重新计时。备注：在当前动画播放过程中有玩家离线切后台等，不会因此中断原本的动画流程"。全文检索"重连/恢复"无任何场景恢复描述。
- **基准依据**：04#1 场景应答恢复倒计时基准与记牌器；04#3 行牌快照恢复固定顺序（开局数据→玩家→配置→局数据→牌墙→手牌→河牌→权限→倒计时/方位灯→end_wait 应答）；04#6 他人手牌恢复为背面；04#8 权限与按钮按位完整恢复、他人权限立即收操作区；04#9 河牌恢复后补出牌放大；04#13 end_wait 自动应答防服务端卡死；04#18 重连后在托管态弹遮罩（无托管不适用，但恢复顺序适用）。
- **问题**：需求只定义了断线图标与计时，未定义断线玩家重连后如何恢复牌局：恢复哪些内容、按什么顺序、恢复期间动画是否静默、他人手牌是否翻开、倒计时以什么为基准、权限按钮如何还原、最后出牌放大是否补显。
- **影响**：好友房 8 局对局时长内断线必然发生；无恢复规格则该场景无法开发与验收，服务端 end_wait 应答缺失还会导致整桌卡死。
- **建议**：新增"断线重连与场景恢复"章节：恢复入口与状态分发、恢复顺序、静默模式（不播开局/摸牌/胡牌动画）、他人手牌背面、权限/倒计时/方位灯/出牌放大补刷、end_wait 自动应答；可直接以基准 04#1~#16 为对照逐条声明采纳或改版。
- **验收口径**：行牌中断线重连后，本家手牌/河牌/牌墙/剩余数/权限按钮/倒计时/方位灯与断线前一致，他人手牌保持背面，最后出牌放大补显；开局/发牌/洗牌阶段断线重连各有定义的恢复表现。
- **处理状态**：待确认

### Q02【P0 / MISSING】杠操作按钮组与加杠/暗杠触发交互完全未定义

- **问题性质**：核心操作（杠）缺少全部 UI 入口定义；碰、吃、胡均有按钮规格，唯独杠没有。
- **原文**：位置"三、对局流程 → 局内流程 → 吃碰杠胡操作 → 杠牌"。引文（全文）："杠牌-复用现有血战杠的特效，主要区别删除刮风下雨，无论什么杠，统一使用杠字即可"。
- **基准依据**：01#3 操作区控制器页面状态（碰杠胡态/选择多杠态）；01#9 杠单组合直接发送、多组合进入选择多杠态显示牌面列表、多杠态点取消=同时执行过。
- **问题**：未定义：他人弃牌可直杠时是否显示【杠】+【过】按钮组及位置；本人出牌阶段加杠、暗杠的触发方式（点击手牌第 4 张弹选项？按钮？）；多种杠组合并存时的选择交互；杠按钮与过按钮的互斥/收起规则。"复用血战杠的特效"仅指动画特效，不构成按钮交互规格。
- **影响**：杠是本期启用的高频核心操作（含吃碰当前回合可杠），无入口定义无法开发与验收；暗杠 3 背 1 正的展示虽有玩法描述，但玩家如何发起暗杠无解。
- **建议**：补充杠操作小节：直杠按钮组（样式/位置/与碰胡并存时的排布）、加杠与暗杠的出牌阶段触发交互、多杠组合选择列表、选择态取消=过的行为。
- **验收口径**：可直杠时出现杠按钮且点击后弃牌入副露并补牌；出牌阶段可按定义的交互完成加杠/暗杠；多种杠并存时出现选择列表，取消等同过。
- **处理状态**：待确认

### Q03【P1 / CONFLICT】单击出牌前后矛盾

- **问题性质**：文档内部矛盾，同一功能两处口径相反。
- **原文**：位置一"局内流程 → 行牌操作 → 出牌（前表）"。引文："单击出牌：出牌阶段点击打出不可听牌的牌，则直接将其打出，无需提起。单机出牌开启时，若轮到自己出牌前有牌提起，则自动下落。"位置二"行牌操作｜修改对比版 → 出牌"。引文："本方案默认双击出牌。滑动出牌默认开。单击出牌归设置模块，本方案不包含该模式。"
- **基准依据**：01#12 三种出牌方式均为设置项控制（单击直接出需设置开启）；01#13 打听牌禁止单击直接打出。
- **问题**：前文将单击出牌作为本期可选出牌方式给出完整交互定义（含自动下落细节），后文明确"本方案不包含该模式"，范围互相矛盾；另"单击仅限不可听牌"的限制依附于被排除的模式，本期双击/滑动模式下可听牌能否滑动直接打出也未说明（基准 01#13 要求打听牌强制先提牌查看听牌信息）。
- **影响**：开发无法确定单击出牌是否在交付范围；可听牌的滑动出牌限制缺失可能导致绕过听牌提示交互。
- **建议**：删除或标注前文单击出牌段落为"原方案对照"；补充说明本期双击/滑动模式下可听牌是否允许滑动直接打出（基准要求禁止单击直接打出、须先提牌）。
- **验收口径**：全文仅存在一种口径；滑动出牌对可听牌的限制有明确结论。
- **处理状态**：待确认

### Q04【P1 / INCOMPLETE】"多操作状态"章节空引用

- **问题性质**：章节只有标题、无任何内容；该状态在本期必然发生。
- **原文**：位置"三、对局流程 → 局内流程 → 吃碰杠胡操作 → 多操作状态-复用功夫川麻"。引文：仅有标题"多操作状态-复用功夫川麻"，其后直接进入"对局内通用提示"，无正文。
- **基准依据**：01#3 操作区按权限组合切换页面状态；01#4 他人收到权限时自己操作区直接收起（关按钮区、锁手牌、清提示）；01#25 操作区收起的统一时机。
- **问题**：同一弃牌多人可响应（庄闲放铳下多人可胡、胡与碰并存）是本期规则明确支持的裁决场景，但各端按钮如何同时展示、裁决后未获权玩家的按钮如何收起、操作区互斥规则全部缺失，仅以外部项目名"功夫川麻"代替。
- **影响**：多人响应是常见分支，按钮残留/误操作风险高，无法验收。
- **建议**：补写多操作状态：各端按钮同时展示规则、他人权限到达时本家操作区立即收起、裁决完成后按钮区与方位高亮的联动切换。
- **验收口径**：两人同时收到按钮时各自界面按钮正常；一方胡/碰成立后另一方按钮立即消失且手牌恢复可操作态。
- **处理状态**：待确认

### Q05【P1 / INCOMPLETE】满 8 局"结束本场"的表现未定义

- **问题性质**：本期核心流程的终点缺失；大结算被列为不做，但结束本场后的界面表现没有任何定义。
- **原文**：位置"本期开发范围"。引文："每小局保留小结算，未满8局则继续下一小局，满8局结束本场。""本期只做游戏内核心流程。原文中的创房面板、其他玩法选项、大结算和非核心桌面功能，如在核心段落中被引用，仅作原文上下文。"
- **基准依据**：03#17 大结算数据组装（总局数/起止时间/总分/明细）；03#18 大结算弹出时机（动画链第 4 步延迟 2 秒/解散局直出）；03#19 收到大结算事件后小结算强制切"最后一局"页；03#14 最后一局继续按钮转弹大结算。
- **问题**：固定 8 局是本期规则，第 8 局小结算后玩家看到什么（大结算不做）未定义：直接解散回大厅？停留小结算？还是简化总分页？第 8 局小结算的"继续游戏"按钮行为也随之下落空。
- **影响**：8 局打完是必现场景，终点表现缺失导致整场流程无法走通验收。
- **建议**：明示第 8 局结束本场的表现（即使简化，也应定义：显示汇总分或直接回房间/解散），并定义最后一局小结算按钮文案与行为。
- **验收口径**：第 8 局小结算操作后有明确定义的结束表现，玩家可离开对局且房间状态可预期。
- **处理状态**：待确认

### Q13【P2 / INCOMPLETE】手牌标注体系不完整（典型 P2 之一）

- **问题性质**：手牌高亮/置灰/特殊标注的规则只覆盖了碰与吃两个场景，且缺清除时机与局内财神标识。
- **原文**：位置"吃碰杠胡操作 → 碰牌-复用"。引文："手牌中可碰牌高亮其他暗置，如果有胡则不需要暗置"；"吃碰杠胡操作 → 杠牌"仅有特效一句话；手牌信息章节无财神角标描述（仅小结算提到"手牌里的财神也有需要染色"）。
- **基准依据**：01#15 有碰或杠权限且无胡权限时除目标牌外整手置灰，有胡权限清灰；01#16 置灰颜色优先级 黄 > 灰 > 财神红 > 正常；01#17 置灰清除时机（点碰/杠/过、收操作区、他人权限到达）；07#12 手牌癞子角标按配置牌表设置黄色角标。
- **问题**：a) 权限为杠（含直杠/加杠/暗杠候选）时手牌哪些牌置灰/高亮未描述；b) 置灰何时清除（出牌后、点过、他人权限到达）未描述；c) 局内手牌财神无角标/染色定义，玩家无法识别手中哪张是白板财神；d) 胡权限与碰/杠权限并存时的置灰豁免仅一句"如果有胡则不需要暗置"，与基准的清灰口径需确认一致。
- **影响**：手牌状态表达不一致会导致误出牌与验收争议；财神不可见直接影响白板财神玩法的可玩性。
- **建议**：补齐杠权限置灰规则、置灰清除三时机、局内手牌财神角标（样式/位置），并声明与基准四色优先级（黄>灰>财神红>正常）是否一致。
- **验收口径**：碰/杠/吃权限下置灰范围符合定义；出牌或点过后置灰清除；手牌财神有可见标识。
- **处理状态**：待确认

### Q14【P2 / INCOMPLETE】听牌提示体系不完整（典型 P2 之二）

- **问题性质**：只定义了"提牌联动弹窗"一个入口和标签规则，弹窗结构、主动查看入口、箭头生命周期缺失。
- **原文**：位置"手牌信息 → 听牌标签显示规则"与"行牌操作｜修改对比版 → 提牌"。引文："提起候选牌时，面板显示该牌打出后可胡的牌面及各自剩余张数。改提另一张候选牌时更新面板。取消提牌、改选非候选牌或实际出牌后收起面板。"
- **基准依据**：02#8 常驻听牌组件含查听按钮，显示条件为有已听牌数据且自己未胡，及成套显隐时机；02#9 弹窗每项=牌面+倍数+剩余张数、番数降序+牌值升序、剩余 0 张置灰、总张数+封顶文案；02#10 弹窗两入口（查听按钮重复点击切换/提牌自动弹）；02#11 弹窗关闭时机（摸牌、可胡、自己胡、流局摊牌、点桌面等）；02#5 自己胡后听牌数据清空、清箭头；02#6 出牌后仍保留有效箭头。
- **问题**：a) 无查听按钮，已听牌玩家无法主动查看全局听牌；b) 弹窗缺倍数列、排序规则、剩余 0 张置灰、总张数与封顶文案（本期无封顶时的文案）；c) 弹窗/箭头的关闭与保留时机只写了三条（取消提牌/改选/出牌），摸牌、获得胡权限、自己胡、流局、点桌面空白均未定义；d) 听牌箭头出牌后是否保留未定义。
- **影响**：听牌提示是牌手核心决策辅助，入口与生命周期残缺会直接造成交互回退或状态残留。
- **建议**：按基准 02#8~#11 补齐：查听按钮显隐时机、弹窗信息结构（含无封顶文案）、关闭时机清单、箭头出牌后保留与胡后清除。
- **验收口径**：已听牌可见查听入口；弹窗含牌面/倍数/剩余数且 0 张置灰；摸牌、胡牌、流局等各时点弹窗与箭头状态符合清单。
- **处理状态**：待确认

### Q22【P2 / MISSING】小结算继续/关闭交互与下一局衔接未定义（典型 P2 之三）

- **问题性质**：小结算界面只定义了静态展示项，没有任何退出/继续交互，8 局循环无法推进。
- **原文**：位置"结算界面 → 小结算界面（好友房）"。引文：触发逻辑仅"播完胡牌结算流程，进入结算界面"；UI 交互说明仅列玩家信息、手牌摆布、输赢显示、分数结算、承包标识、赢家结算、麻将牌标识、财神牌八项，无任何按钮。
- **基准依据**：03#14 继续游戏按钮：最后一局转大结算，否则关小结算+自动准备下一局；03#15 关闭按钮：好友房直接关；03#18 小结算为动画链第 3 步、大结算第 4 步的先后关系。
- **问题**：未定义：小结算上的按钮集合（继续/关闭）；单人点击即关还是全员确认才开下一局；点击后到下一局摇骰的过渡；与 Q05 的第 8 局终点衔接。
- **影响**：局与局之间无法推进，好友房多人场景下"谁点了才算数"无标准会产生流程挂起或抢开。
- **建议**：定义按钮组与多端确认规则（建议沿用基准：继续=关小结算并进入下一局准备，全员确认或房主开局的口径需明确），并与 Q05 一并给出第 8 局分支。
- **验收口径**：任意一局小结算后按定义操作可稳定进入下一局；第 8 局走 Q05 定义分支。
- **处理状态**：待确认

## 4. 总体建议

1. **问题最多模块**：吃碰杠胡操作（Q02/Q04/Q15/Q16/Q17/Q18/Q27/Q28/Q29，约 9 条）与结算链/小结算（Q05/Q09/Q19/Q20/Q21/Q22/Q40，约 7 条）。前者缺的是操作入口与生命周期骨架，后者缺的是演出顺序与界面外交互，两块都需要成段补写而非零星修句。
2. **是否建议进入开发**：**暂不建议直接进入全量开发**。建议处理顺序：
   - 先补 P0 两项（断线重连章节、杠操作入口）与 P1 三项（单击出牌口径、多操作状态、第 8 局终点）——这五项不解决，核心流程无法走通与验收；
   - P2 中 Q10（补牌方向）、Q11（悬空编号）、Q12（准备规则）属于低成本高收益的文字级修订，可随首修订版一并处理；
   - P3 项可在开发期内以差异说明附录形式补充（财神指示牌、爆/飘标签、吃按钮均为现网不存在的新增功能，按基准口径应标注"与现网实现的差异"）。
3. **方法建议**：需求中"复用功夫川麻""同步老包""参考血战杠特效"类外部引用，建议改为"引用目标 + 差异清单"的写法，逐条声明与杭麻现网（42319）一致或改版，避免验收时无据可依。
