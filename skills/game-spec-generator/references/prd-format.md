# PRD 格式规范

> 模板：`templates/PRD.template.md`（改编自 game-ui-design-workflow spec-kit，MIT）

## 职责

回答「产品要做什么」。承载功能、场景、流程、验收标准——玩法细节归 GDD，页面操作归 Interaction。

## 必须覆盖的章节

1. 文档状态
2. 事实溯源汇总
3. 概述（目标 / 可验证的成功指标 / 非目标）
4. 用户与场景表
5. 功能需求（P0/P1/P2 表格，每条含：对应页面/系统、关联 GDD 规则、验收标准、来源事实）
6. 业务流程（端到端）
7. 配置功能
8. 异常场景（掉线/人数不足/解散/超时等非正常路径）
9. 与下游文档关系

## 硬性规则

- 每条需求必须可被页面或组件承接，并关联 GDD 规则（GDD-Rxxx）
- 验收标准必须可验证（能写出测试场景）
- 非目标必须明确（防止范围蔓延）
- 异常场景不得遗漏原文提到的非正常路径
