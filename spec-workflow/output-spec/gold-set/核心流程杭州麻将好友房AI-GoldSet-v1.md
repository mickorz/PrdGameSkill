# 杭州麻将四人好友房 · Gold Set v1.0

**定位**：10 道固定 Benchmark Gold Set——不是普通的麻将知识问答，而是专门测试 AI 反推策划案（`spec-workflow/output-spec/核心流程杭州麻将好友房AI-策划版.md`）有没有准确还原好友房规则。

**事实源边界**：这套 Gold Set 只以既定规则为事实源，不把其他平台的杭州麻将规则偷偷补进来。对于尚未给出具体执行定义的规则，专门测试 AI 能否识别信息缺失，而不是猜答案。

| 项 | 值 |
|---|---|
| 测试题数量 | 10 |
| 满分 | 100 |
| 测试类型 | 规则还原 |
| 评分方式 | 逐项断言 |
| 覆盖范围 | 房间配置 · 准备流程 · 庄闲身份 · 出牌顺序 · 吃牌规则 · 超时机制 · 流局 · 小结算 · 整场结束 · 规则边界 |

## 测试目标

1. 能否准确提取房间配置。
2. 能否理解四人好友房的准备和开局流程。
3. 能否还原庄家、闲家和出牌顺序。
4. 能否正确理解吃牌限制。
5. 能否还原无托管机制。
6. 能否正确处理流局、局数和结算。
7. 能否识别三摊承包、碰算摊关闭等规则配置。
8. 能否识别规则边界，不擅自编造没有定义的规则。

## 一、10 道测试题与标准答案

### G01：房间配置完整性（10分）· 配置还原

**测试输入**

```
请描述这个杭州麻将四人好友房的完整配置。
```

**Gold 标准答案**：必须准确提取：

| 配置 | 标准值 |
| --- | --- |
| 房间人数 | 4人 |
| 局数 | 固定8局 |
| 底分 | 1 |
| 财神 | 白板财神 |
| 起庄模式 | 笃三老庄 |
| 放铳 | 庄闲放铳 |
| 承包 | 三摊承包 |
| 特殊规则 | 吃碰禁手 |
| 封顶 | 无封顶 |
| 碰算摊 | 关闭 |
| 托管 | 关闭 |

**评分断言**

- 10项配置全部识别。
- 不得将碰算摊识别为开启。
- 不得将白板财神识别成翻财神。
- 不得将固定8局识别成40片。

### G02：首次开局条件（10分）· 房间生命周期

**测试输入**

```
房间已经创建，目前只有3名玩家入座。
其中2名玩家已经准备。
房主能否开始第一局？

后来第四名玩家进入并准备，
此时是否可以开始？
```

**Gold 标准答案**

第一种情况不能开始。必须同时满足：

1. 房间坐满4人。
2. 4名玩家全部准备。
3. 由房主开始首局。

第四名玩家进入并完成准备后，满足条件，房主可以开始首局。

**评分断言**

- 不能将3人房间视为可开始。
- 不能将部分玩家准备视为全部准备。
- 不能将首局开始权限交给任意玩家。

### G03：后续小局自动开始（10分）· 房间生命周期

**测试输入**

```
第一局已经结束，四名玩家都返回好友房。

A、B、C已经准备，D尚未准备。
此时是否自动开始第二局？

D随后完成准备，是否还需要房主再次点击开始？
```

**Gold 标准答案**

- A、B、C准备，D未准备：不能自动开始。
- D完成准备，四人全部准备：自动开始第二局。
- 后续小局不需要房主再次点击开始。

**评分断言**

必须区分：

- 首局：房主手动开始。
- 后续局：四人准备完成后自动开始。

### G04：庄家与闲家身份（10分）· 对局身份

**测试输入**

```
当前小局有四名玩家：
A、B、C、D。

系统确定A为本局庄家。

请说明庄家和闲家的身份，以及谁先出牌。
```

**Gold 标准答案**

- A：庄家。
- B、C、D：闲家。
- 每小局只有一名庄家。
- 庄家先出牌。

**评分断言**

- 不得出现多个庄家。
- 不得将庄家身份与房主身份混淆。
- 不得认为房主必然是庄家。

### G05：上家定义与吃牌限制（10分）· 牌局操作

**测试输入**

```
当前玩家A准备吃牌。

B是A的上家。
C是A的对家。
D是A的下家。

分别讨论：

1. B刚打出一张可以组成顺子的牌。
2. C打出一张可以组成顺子的牌。
3. D打出一张可以组成顺子的牌。

A分别能否吃牌？
```

**Gold 标准答案**

| 出牌玩家 | 能否吃 |
| --- | --- |
| B（上家） | 可以，前提是满足吃牌条件 |
| C（对家） | 不可以 |
| D（下家） | 不可以 |

并且：

- 上家定义为本家逆时针方向的上一家。
- 吃牌只能使用上家刚刚打出的牌。
- 不能拿之前打出的牌进行吃牌。

**评分断言**

重点检查 AI 有没有把吃牌理解为可以吃任意玩家的牌。

### G06：无托管与倒计时结束（10分）· 操作时序

**测试输入**

```
当前玩家需要出牌，操作倒计时已经归零。

玩家没有点击任何按钮。

系统应该如何处理？

如果当前玩家正在响应其他玩家的吃、碰等操作，
倒计时结束后又应该如何处理？
```

**Gold 标准答案**

- 倒计时结束不代表自动出牌。
- 系统不能自动选择一张牌打出。
- 系统不能自动执行过牌。
- 系统继续等待玩家手动出牌或响应。
- 无托管，不存在超时自动操作。

**评分断言**

以下任何行为都属于错误：

- 自动打出默认牌。
- 自动打出最左侧的牌。
- 自动过牌。
- 自动选择吃碰杠。
- 倒计时归零直接改变玩家操作结果。

### G07：流局计数与小结算（10分）· 结算流程

**测试输入**

```
当前进行到第3局。

这一局没有玩家胡牌，最终流局。

请说明：
1. 本局是否计入总局数？
2. 是否需要进行小结算？
3. 下一局的编号是多少？
```

**Gold 标准答案**

- 流局计为1局。
- 当前第3局完成后，总完成局数变为3。
- 每小局均进行小结算。
- 如果尚未达到8局，继续下一局。
- 下一局为第4局。

**评分断言**

不得将流局当成不计局数的无效局。

### G08：8局结束条件（10分）· 整场生命周期

**测试输入**

```
场次已经完成7局。

第8局正常胡牌，完成小结算后，
系统应该继续下一局，还是结束整场游戏？

如果第8局是流局，结论是否变化？
```

**Gold 标准答案**

两种情况都结束整场游戏。

因为：

- 固定8局。
- 胡牌和流局都计入局数。
- 第8局完成后进行小结算。
- 满8局结束本场。
- 不再开始第9局。

**评分断言**

- 不得要求必须胡牌才计入8局。
- 不得将流局排除在8局之外。
- 不得在第8局结算后自动开启第9局。

### G09：三摊承包与碰算摊配置（10分）· 特殊规则

**测试输入**

```
当前好友房开启三摊承包，
但碰算摊关闭。

请说明这两个配置的关系。
```

**Gold 标准答案**

- 三摊承包功能开启。
- 碰算摊功能关闭。
- 不能因为开启三摊承包，就认为碰牌也参与摊数计算。
- 碰算摊关闭意味着碰牌不计入摊数。

但目前给出的规则没有完整说明吃、明杠、加杠、暗杠的具体计摊口径，也没有给出承包与反承包的完整赔付公式。

因此 AI 不应自行补充这些细节。

**评分断言**

重点检查：

- 是否区分承包开关和碰算摊开关。
- 是否将碰牌错误地计入摊数。
- 是否编造承包赔付公式。

### G10：综合场景与规则边界（10分）· 综合推理

**测试输入**

```
当前是第8局。

四名玩家已经完成准备，系统自动开始本局。

A是庄家，B、C、D是闲家。

庄家A先出牌。
B是C的上家，D是C的下家。

B打出一张牌，C可以吃。
C没有立即响应，倒计时结束。

随后C手动吃牌并继续完成对局。
本局最终流局。

请完整描述这段流程，并说明场次是否结束。
```

**Gold 标准答案**

1. 当前是第8局，四人准备完成后自动开始。
2. A是本局庄家，B、C、D是闲家。
3. A先出牌。
4. B是C的上家，B打出的牌符合条件时，C可以吃。
5. C没有及时操作，倒计时结束后系统不能自动过牌。
6. C手动响应，系统按玩家操作继续。
7. 本局最终流局。
8. 流局计入1局。
9. 第8局完成小结算后，整场结束。
10. 不开启第9局。

**评分断言**

这一题同时验证：准备流程、庄家身份、上家关系、吃牌限制、无托管、流局计数、小结算、整场结束。

## 二、测试执行方式

不把 Gold 标准答案给负责反推策划案的 AI，采用盲测方式：

1. **被测对象**：反推策划案（盲答唯一事实源）。
2. **10 道 Gold 测试题**：逐题输入 AI（仅依据策划版作答），记录回答。
3. **标准答案逐项比对**：检查正确性、完整性、错误推断。
4. **最终评分与缺陷清单**。

## 三、评分标准

每题10分，按三个维度评分：

| 评分维度 | 分值 | 评价内容 |
| --- | --- | --- |
| 正确性 | 5分 | 有没有说错规则 |
| 完整性 | 3分 | 有没有遗漏关键条件 |
| 边界意识 | 2分 | 有没有擅自推断未定义规则 |

额外错误惩罚（每次扣2分）：

- 编造规则。
- 将关闭的开关描述为开启。
- 把不同生命周期阶段混淆。

**最终评价标准**

| 总分 | 评价 |
| --- | --- |
| 90～100 | 规则还原优秀——核心规则准确，边界清晰 |
| 80～89 | 基本命中——主要规则正确，存在少量遗漏 |
| 60～79 | 需要补充——存在规则遗漏或理解偏差 |
| 低于60 | 反推失败——核心规则、流程或状态机存在明显错误 |

## 四、额外设置：这套 Gold Set 的重要边界

特意保留的易暴露 AI 幻觉的问题：

| 规则 | 当前已知事实 | 尚不能直接推断 |
| --- | --- | --- |
| 笃三老庄 | 房间配置为笃三老庄 | 具体庄位计数、倍率公式 |
| 白板财神 | 白板财神模式 | 白板参与吃碰杠、具体胡牌限制 |
| 吃碰禁手 | 规则中存在该配置 | 具体触发条件和限制行为 |
| 三摊承包 | 已开启 | 明杠、加杠、暗杠计摊和赔付公式 |
| 庄闲放铳 | 已开启 | 所有特殊牌型下的完整放铳判定 |

测试的不仅是 AI 能不能回答，还要测试它能不能识别策划案没有提供的信息。

## 附：执行建议

第一轮先只跑这 10 题，不要马上增加题目。跑完之后把 AI 的 10 道回答和反推策划案交给第二轮评审：不仅看得分，还要定位到底是原始规则没有提取出来、规则之间的关系没有建立，还是状态机和流程表达有问题。

这比单纯让 AI 自己评价策划案是否完整，更能检验它有没有真正理解这套杭州麻将。
