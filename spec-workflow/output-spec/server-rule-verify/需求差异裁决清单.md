## 条目一：AT-ST-C02-008 财神打出后按普通白板留在牌河

**需求原文**：财神打出后按普通白板的形态留在牌河，不再作为财神参与后续牌局。

**双栏对照**：

| 需求拆句 | 实现表现 | 结论 |
|---|---|---|
| 前半句：打出后**按普通白板形态**留在牌河 | 客户端：牌河与出牌放大牌面都会重新刷财神红，打出的白板财神仍被高亮标识为财神（出牌区列表 `BoxHzmjMah2DView.ts:1127-1132`；出牌放大 `BoxHzmjMainView.ts:1044-1054`）——已观察 UI 表现，作用域恒为 active | **冲突**（视觉冲突独立成立） |
| 后半句：**不再作为财神参与后续牌局** | 服务端：财神注册后即从吃碰杠候选组移除实际财神，打出的财神不再参与吃碰杠（`common_game/com_game/common_game_com_ju.cpp:248`，BoxJokerStep::Execute；翻财神时白板登记为替代牌） | 一致（受 cai_shen_type 配置影响：创房默认白板财神 0，玩家可选翻财神，RuleHzmj.ts:27/265-275 → 判 conditional） |

**复核结论**：服务端规则与后半句方向一致，但前半句的客户端视觉冲突不因服务端规则正确而消除（复核规则 `ui-conflict-stands-alone`）→ 差异维持 **conflict**，L7 判 **decision_required**，转人工裁决。

**裁决问题**（牌河财神高亮的表现口径）：

- [ ] A. 改客户端：打出的财神在牌河/出牌放大处按普通白板显示，去除财神高亮（以需求为准）
- [ ] B. 改需求：接受打出的财神保持财神高亮（便于玩家追踪财神去向，以现状实现为准）
- [ ] C. 其他：__________（请备注期望行为）

## 附 B：复核规则速查（设计文档 4.2）

| 规则 | 含义 |
|---|---|
| `evidence-is-not-consistency` | 找到直接实现证据，允许差异升级 |
| `no-server-evidence-is-not-conflict` | 缺服务端证据不等于冲突（维持原差异） |
| `common-capability-is-not-enabled` | 通用能力入口存在不等于当前玩法启用 |
| `ui-conflict-stands-alone` | 客户端视觉冲突独立成立，不因服务端规则正确而消除 |

差异变更流程：pending（本清单待裁决）→ 人工批准 approved → 合并进 v3 索引（S3.3）；v2 基线全程只读。
